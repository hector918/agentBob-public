# heartwood：共享基础原语

`heartwood/` 是唯一允许被任何 leaf / flow 模块**直接 import** 的实现层，收拢那些「必须处处行为完全一致」的原语。

## 在架构中的位置

heartwood 位于 [contract](contract.md) 之上、[trunk](trunk.md) 之下（见 [架构总览](../architecture.md)）。它不是模块层，但其中三个包各自注册了一个 trunk 模块，因为它们有生命周期要管：

| 节点 | Provides | Needs | 软边（`TryRequire`） |
|---|---|---|---|
| `prompt` | `contract.PromptFactory` | — | — |
| `clock` | — | — | `contract.DB` |
| `files-sweeper` | — | — | `trunk.Housekeeper` |
| `scrub` | 不注册模块（纯函数库） | | |

上下游：`contract.PromptFactory` 的消费方是两条主流程 `flow/normal` 与 `flow/agora`（见 [flows.md](../flows.md)）；`contract.DB` 由 `pgpool` 提供；`trunk.Housekeeper` 由脊梁自身提供，不经模块图。

准入门槛写死在架构守卫里（`arch/50-heartwood_test.go` 的 `heartwoodAllowed`）：往 `heartwood/` 加一个包会让测试变红，必须显式登记才放行。这道闸的判据是三条同时成立——真正被多方共享、没有向上依赖、**且结果必须处处逐字节一致**。单消费者的辅助函数不算，带重外部依赖（转码器、网络后端）的子系统也不算。

## 功能

四个包解决的是同一类问题：某个语义如果在两个模块里各写一份，两份会悄悄漂开，而漂开的后果不是编译错误，是运行期的错判。

- 提示词卫生与体积估算漂开 → 注入防线在一条路径上失效，或压缩与选路对同一段历史算出两个大小。
- 时间标尺漂开 → 多进程写同一个库时审计顺序错乱。
- 附件落盘规则漂开 → 沙箱逃逸或磁盘无界增长。
- 凭证脱敏漂开 → 一条路径把密钥原样喂给了模型。

heartwood 的存在就是把这四件事各自钉成一份实现。

## 内部结构

### clock —— 进程时钟与时间戳拼写

`clock` 有两个互不相干的职责，共用一个包名，因为它们回答的是同一个问题「这个时刻怎么表达」。

**校准后的进程时钟。** 宿主机时钟与数据库时钟会漂（NTP、跨主机部署），而多个进程写同一个库时需要**单一时标**，否则审计排序失真。`clock.Module` 在 `Start` 时向数据库读一次服务端 now()，取查询窗口的本地中点抵掉一半 RTT，算出 `offset = serverNow − localNow`，之后每小时重校一次。`clock.Now()` / `UnixSeconds()` / `UnixEpoch()` 返回的都是「本地 + offset」，落在数据库的时标上，且一律 UTC。

失效是安全的：拿不到 DB 或校准失败，offset 保持 0，等于退回裸 `time.Now()`——比原来不差，只是少了校准，并且 WARN 记一笔。

**两种时间戳拼写。** `clock.Stamp` 用于面板里可能显示「旧」东西的地方（配置的修改时间、上次运行水位），带年份——少了年份，同一天与去年同一天长得一模一样，而面板恰恰是陈旧痕迹必须一眼可辨的地方。`clock.TimeOfDay` 只用于必然新鲜的实时表格，秒才是有信息量的部分。两者都把零值渲染成破折号：「从未」是一个真答案，不该被显示成公元一年。

这两个函数都渲染**本地时区**，而日志一律 UTC（见 [infra.md](infra.md)）——这是刻意相反的：日志被拿来互相对齐，面板被一个站在某个时区里的人阅读。

### files —— 附件暂存与磁盘清扫

`files.Store` 是一个**与会话作用域无关**的落盘暂存桶：source 在会话作用域尚未解析出来时就得把入站字节写下来，于是先落到 `$BOB_HOME` 下的 sandbox 树里，按 `<来源>/<YYYY-MM-DD>/` 分桶；等提交管线定下作用域，再把被接受的文件移进该作用域的 space。

`Save` 承担三件防御：文件名清洗成安全字符集；拼出的目录必须仍在 base 之下（`filepath.Join` 会吃掉 `..`，所以要显式复核）；以及**硬性字节上限**——`io.CopyN` 只读到上限为止，再探测一个字节判断是否超限，因此一次恶意上传最多占用恰好上限的磁盘，而不是「上限 + 1」。

`files.Sweeper` 是清扫侧的 trunk 模块：它不自己转定时器，而是软取 `trunk.Housekeeper` 注册一个周期任务，让所有重磁盘扫除在同一处排队。清扫分两片策略：

- **暂存树**：按日期目录的年龄裁剪，外加可选的总字节上限。**今天的目录豁免于上限**——刚落盘、还没被放置的在途附件就住在那儿，把它删掉等于弄丢用户正在发的文件；上限的职责是长期增长，接受最多一天的有界超额。
- **space 树**：按空间**类型**分两种策略。共享存储空间承载生命周期长于任何会话的协作数据，只裁剪其中的入站子目录，根下的共享文件永不删；其余的每作用域工作空间是会话草稿区，整棵树按 mtime 递归裁剪——真正的交付物早已通过投递工具离开、可再生的中间产物下次用时会重新生成。

清扫走的是 `os.Root` 钉住的目录 fd 而不是路径字符串：space 目录本身是模型可写的，路径式遍历会给出「检查与删除之间把目录换成符号链接」的窗口，从而删到空间之外。连「指向空间内部」的链接也一并拒绝——扫除只应触碰真实的那个子目录。

### prompt —— 提示词构建、文本卫生与体积估算

`prompt` 提供 `contract.PromptFactory`，但它是**哑的**：一个 builder 就是一串有序的具名层，`SetLayer` 第一次设定某层时钉死它的渲染位置，之后再设只更新内容；`Build` 把非空层拼起来。builder 不知道任何一层是什么意思——所有与上下文的耦合都留在流程层。也正因为 builder 不持有会话状态，这个模块既不需要存储也不需要协作者。

同包里另外两组东西才是它必须住在 heartwood 的原因：

**文本卫生。** 结构化提示词里有 `[名字]:` 这样的元结构，而显示名和被引用的文本都来自不可信输入。`SanitizeSpeaker` 剥掉方括号与换行并限长，`SanitizeQuoted` 额外把双引号降级、按预算截断，`StripControl` 清掉所有会打断单行契约的控制字符（C0、DEL、C1，以及 U+2028/2029）——但**不截断**，因为附件路径要被原样回显才能解析。这套防线在若干处被独立地渲染（回合核的说话人前缀、流程层的逐事件渲染、会话的快速插话通道），任何一处漏一份就是一个可注入的缺口。

`QuotedMediaNote` 是这条线上一个措辞即行为的例子：当用户回复的那条消息带着图片时，引用块里需要一句说明。实测下来，带方括号的标记会被卫生函数剥成裸词，读起来像是父消息的**正文**，模型于是去找一个叫那个名字的文件；而只点出媒体类型比裸词更糟——它断言了图片的存在，把模型推得更用力去找。真正结束这件事的是明说「够不着」。所以这个函数收一个「是否在本轮附件里」的参数：那句话必须是真的，因为有些平台确实会把被回复消息的媒体一并下载进本轮。

**体积估算。** `EstTokens` 按字符类估算：宽字符（中日韩、假名、谚文、全角）算 1，其余算 0.25。粗糙是刻意的，一致才是重点——回合核的压缩触发和模型池的上下文窗口预选路**必须**用同一个估算，否则一边把历史压到另一边会拒收的预算上。`EstTokensMsg` 还把 assistant 行的工具调用参数计进去，因为大参数调用往往才是体积的主体。

### scrub —— 凭证脱敏

`scrub.Scrub` 对任何即将喂给模型的自由文本（工具输出、历史消息、磁盘读入）做一遍凭证形状的redaction，命中一律替换成同一个标记，让模型看到「这里本来有东西、它被有意丢掉了、别去重建」。

模式的设计取向是**保守**：每条都锚在一个高信号 token 上——PEM armor、已知服务前缀、OpenSSH 的 base64 magic、URL userinfo 里的口令段、以 `_TOKEN`/`_SECRET`/`_PASSWORD` 结尾的环境变量名。漏杀是可以接受的（路径策略与凭证代理边界仍在防），而误杀会把正常的工具输出打成马赛克、悄悄降低模型的回答质量，那更糟。

几处细节值得记：

- 成对的 PEM 块先做一遍惰性匹配，**之后**才轮到「孤儿 BEGIN」兜底——上游按字节预算头部截断长输出可能切掉 END 标记，此时任何还立着的 BEGIN 按构造就是不成对的，从它一路 redact 到串尾。
- OpenSSH armor 的三种 base64 对齐旋转都要匹配：密钥前面多 1–2 个字节再编码，整个量子会移位。
- 提供商 API key 的模式必须捕获左边界并在替换里还原（Go 的 RE2 没有 lookbehind），否则以那几个字母结尾的连字符 ID 会被从中间吃掉——正是包文档禁止的那类误杀。
- 200 字符以上的裸 base64 只在**额外满足**条件时才 redact（串内含 armor 前缀，或前 100 字符内出现 "PRIVATE KEY"），且每个匹配按它**自己的**偏移量判断邻近性——否则同一段 base64 出现两次时，第二处的真钥会躲过锚点。

## 设计理据

**为什么脱敏有一份「分身」，而且被测试焊住。** 浏览器 sidecar 是一个独立的 Go module（自带 `go.mod`，构建进自己的容器），因此无法 import `heartwood`，只能带一份手抄的 `scrub` 副本。这份副本曾经冻在某个旧版本上，而主副本此后经历了四轮 redaction 修复——漂移穿过了四轮审计都没被发现，因为每轮只读了主副本。现在 `arch/51-scrub-parity_test.go` 逐文件比对两份的字节，任何分歧直接让 CI 变红：「处处逐字节一致」这句承诺从注释变成了被强制执行的不变量。

**为什么 clock 不是一个 leaf 模块。** 它需要被几乎所有 leaf 直接调用（`clock.Now`），而模块之间零 import 是硬规则；做成 leaf 就只能给每个消费者加一条 trunk 边，把一个纯工具调用变成一次能力解析。它的**校准生命周期**确实需要 trunk（要 DB、要后台循环），所以包里同时住着一个 trunk 模块——但那个模块只管校准，不管调用。`files` 与 `prompt` 是同一个形状：工具是直接 import 的，生命周期才走 trunk。
