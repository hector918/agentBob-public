# warrant — 能力授权

系统的安全核心：判断某个主体（principal）能否使用某项能力，并把工具目录、技能目录、凭证库、文件与执行通道**收窄成这一次回合真正被允许的那个子集**。

---

## 在架构中的位置

**Provides**

| 能力接口 | 说明 |
|---|---|
| `contract.Warrant` | 唯一的能力判官：投影、过滤、发放通道、撤销 |

**Needs**

| 依赖 | 用途 |
|---|---|
| `contract.ToolCatalog` （[tools](tools.md)） | 对账授权行、投影时按名查工具 |
| `contract.ChannelPool` （[tools](tools.md)） | 托管发出去的有状态执行通道 |
| `contract.PanelRegistry` （[webui](webui.md)） | 注册权限面板 |
| `contract.SlashRegistry` （[slash](small-modules.md#slash)） | 注册 `/tools`、`/skills`、`/permission` |

**软边（`TryRequire`，缺席即降级）**：`contract.SkillCatalog`（[skills](skills.md)，无技能子系统则不投影技能）、`contract.Broker`（[credentials](small-modules.md#credentials)，无凭证代理则远程空间与凭证解析不可用）、`contract.AdminLine`（策略损坏时叫管理员）、`trunk.Housekeeper`（执行家目录的保留期扫除）。

**消费方**：流程层（[flows](../flows.md)）。流程把它当判官用——自己算出主体，交给 warrant 过滤。

模块声明 `Optional() = true`，但这**不等于**"缺席即放行"。warrant 缺席时，流程投影出的是**零个**工具与技能，而不是整份目录。这条 fail-closed 语义贯穿全模块。

**启动顺序**上还有一条硬约束：技能目录必须比 warrant 先启动，否则 warrant 启动时的对账会对着一份空目录跑，把每一项技能授权都判成"不存在"。这条约束**没有**写成硬依赖——写成硬依赖会让一个缺席的（同样 Optional 的）技能模块把 warrant 整个跳过，而 warrant 一旦缺席，工具授权就整体消失。所以它写成软边加注册顺序，并由架构守卫测试机器校验注册顺序。这里没读到的后果是 fail-closed（技能被拒），不是放行。

---

## 一次回合里的授权长什么样

1. 流程解析出这一次的**主体**（principal）——一个不透明的字符串，怎么算出来是流程的事。
2. 流程向供给方要一份 `GrantSet`：外层单租户走 `Warrant.Grants`，组织内走组织模块自己的投影。
3. 流程把这份投影连同完整的工具规格清单交给 `Authorize`，拿回这一回合的工具袋；技能同理。模型只看见袋子里的东西。
4. 模型调用某个需要磁盘或 shell 的工具时，工具向 `File` / `Exec` 要一条通往某个空间的通道。这是**二级闸**：一级是"这个工具在不在袋子里"，二级是"这个具体资源你碰不碰得着"。
5. 需要凭证的工具走 `ResolveCredential`，拿到的是一个**已构建好的客户端**，不是一份秘密。
6. 权限一旦变化，`Cut` 把这个主体手上还活着的通道全部回收。

**主体与成员是两个标记。** 上下文里可以同时钉着一个主体（按角色，闸门用它）和一个更细的成员标识（按人）。二者分开是因为同一个角色下的不同人可能持有不同的登录态——闸仍然按角色判，但需要按人隔离的东西（比如浏览器登录）按成员分开。成员标记缺省时回落到主体。用上下文携带而不是穿进每一个函数签名，是为了让深层调用方（凭证代理这类）不必让整条链路都改签名。

## 功能

**授权判定。** 一次判定的货币是 `contract.GrantSet` —— 一组已解析的能力字符串（`tool:use:X` / `skill:use:X` / `credential:use:X`）。谁提供这个投影是**供给方**的事（warrant 从自己的矩阵里收集，组织模块从公司权限里收集）；拿它去过滤目录是**判官**的事，而判官只有一个，就是 warrant。集合成员判定只定义一次（`GrantSet.Granted`，精确匹配，空集授予零权限）。

能力字符串只有三族，动词恒为 `use`：

| 形态 | 管的是 | 判在哪 |
|---|---|---|
| `tool:use:<名字>` | 这一回合模型看得见哪些工具 | 批量投影 |
| `skill:use:<名字>` | 这一回合模型看得见哪些技能 | 批量投影 |
| `credential:use:<名字>` | 能不能拿到某一份凭证构建出的客户端 | 单项判定 |

三族共用同一张矩阵、同一套解析、同一套降级，所以"给某人开一项能力"在三种情况下是同一个动作。

**能力面发放。** 授权不止是"能不能调这个工具"，还包括"能不能碰这块磁盘、能不能在这台机器上跑命令"。warrant 把这三种能力面统一在**空间（space）**这个概念下：`File` 发放文件通道，`Exec` 发放执行通道，`Cut` 在权限变化时回收主体手上还活着的通道。

**审计。** 每一次显式的单项判定都落一行 JSONL 决策日志（允许与拒绝都记），每一次批量投影落一行汇总。日志独立成流，与嘈杂的运行日志分开，便于直接过滤查看。

**运维面。** 权限矩阵可以在 webui 面板里编辑并即时生效，也可以改文件后用斜杠命令热重载，无需重启。

## 内部结构

### 策略矩阵与存储缝

矩阵是一张 **主体 × 能力** 的二维表：能力字符串 → 主体 → on/off。引擎侧（`10-policy.go`）只有三样东西——矩阵类型、fail-closed 查询、以及 `PolicyStore` 这条存储缝。

fail-closed 体现在每一层：`policy.allows` 对未知能力、未知主体、甚至 nil 矩阵都返回 false；单元格的值经 `truthy` 解析，一个拼错的值是"关"而不是"开"；`LoadOrFailClosed` 在数据源**存在但损坏**时返回一张空的拒绝一切的矩阵并置 `broken` 标志，而不是留出一个放行一切的缺口。

存储实现只负责读写（`12-store-file.go` 的 yaml 后端），语义全部留在引擎里。这条缝的意义是：将来若把权限搬进数据库（按公司/角色/流程存），换一个 `PolicyStore` 实现即可复用同一套语义，两种后端的降级行为逐字节一致。

文件后端的落盘走 tmp+rename 原子替换，并对键排序，让每次改动都是一份可 review 的 diff。它另外提供一个"原样写入"的路径：当调用方手上是管理员亲手编辑过的文本时，直接写字节，保留注释与顺序，让这个文件始终是一份人能读能改的配置，而不是被程序重排过的产物。

### 与目录对账

`20-reconcile.go` 让矩阵成为已注册能力的**纯镜像**：新出现的能力对所有主体默认 **OFF** 补一行，已经不存在的能力整行删掉。它从不猜测权限——补出来的行一律是关的，管理员事后自己打开。

两条保护：

- **空集不剪枝。** 一个空的"已注册集合"意味着"我不知道"（目录模块没起来），不是"全都被删了"。真实部署总有至少一个工具，所以集合为空时跳过删除，免得一次瞬时故障抹掉全部授权（包括管理员手动打开过的行）。
- **降级只增不删。** 技能目录若因外部扫描失败退回到内置集合，它给出的名单是**已知不完整**的。此时对账切成只增模式，否则那些暂时看不见的外部技能会被连行删除并落盘。这个检查在启动和热重载两处都必须是**实时**的——重载完全可能正好落在降级窗口里。

### 判官：投影与过滤

`30-authorize.go` 是 `contract.Warrant` 的实现。四个动作：

- `Grants` —— 把 warrant 自己的矩阵坍缩成某主体的 `GrantSet`。这是"外层"的供给；组织模块有自己的供给路径。
- `Check` —— 单项判定，一次调用一个决策。这是唯一记审计的判定边界。
- `Authorize` / `AuthorizeSkills` —— 拿着流程给的 `GrantSet` 过滤规格清单，产出这一回合的工具袋 / 技能袋。没被授予的工具直接丢掉，模型根本看不到它们。
- `ResolveCredential` —— 按 kind 扫凭证库，留下被授权的名字，要求**恰好一个**：零个报"没有授权给你的凭证"，多于一个报配置错误（一个成员只应持有一套同类凭证）。秘密始终不离开凭证代理；错误信息只报数量，从不泄露库里的凭证名。

批量投影**刻意不逐项记日志**：它们每回合跑一遍整份目录，逐个记录会把日志冲垮，而且那不是一个"决策"——模型只是从未见过那些工具。所以批量路径每次只落一行汇总（主体 + 这轮被授予的名字），单项 `Check` 才落逐条决策。

矩阵在**原子指针**后面。热重载可以在并发回合读取的同时换进一张新矩阵：读者要么看到完整的旧表，要么看到完整的新表，永远不会看到半张。指针在首次写入前可能是 nil，而查询是 nil-safe 的（拒绝而非崩溃）。写入侧另有一把互斥锁，序列化"读—对账—落盘—换指针"这一串多步更新，否则重载、技能重扫、面板保存三条路径会互相丢失对方的改动（原子指针只保证每次换指针不撕裂，不保证多步更新原子）。

策略在启动时损坏（present-but-corrupt）会置一个标志位，并在**第一次投影**时向管理通道发一条告警（只发一次）。之所以延后到第一次投影而不是启动时发，是因为管理通道可能比 warrant 起得晚。

### 决策日志

`15-decisionlog.go` 是一层薄封装，记录形状归它，追加/封顶/裁剪/句柄缓存的机械归共享的环形文件原语。一条记录约两百字节，默认十兆的软上限能存下相当长一段时间的审计。写到顶时**就地裁掉最旧的一半**继续写，这样文件始终是可解析的 JSONL，跟随查看也不断流。

它是尽力而为的：路径不可写、磁盘满，都只发一条警告然后在本进程生命周期内自我关闭，绝不向判定路径返回错误、也绝不阻塞判定。

### 空间与三种能力面

**空间**是可寻址的工作区。`70-spaces.go` 把空间名映射到后端：不在配置里的空间一律是**本地目录**；声明为 `ssh` 的空间是远程主机，通过一个具名凭证抵达。

配置校验同样 fail-closed：未知的后端名、或者给本地后端配了凭证，都直接判为解析失败，绝不落到本地分支。理由很直白——一个"远程"空间悄悄跑在一个本地空目录里、还顺带跳过了凭证闸，是所有结果里最坏的那个（用户以为在远端跑，其实哪儿也没跑）。配置文件缺失是正常的"全本地"默认；配置文件存在但解析不了，空间路由整体停用。

空间名到路径的解析（`SpaceLocalDir`）是这块的安全关键：

1. **先折叠再校验。** 字符集之外的每一个字符都折成 `_`。这覆盖了各种作用域分隔符（`/`、`:`、`#`）以及聊天 id、成员标识、公司名里可能出现的任何东西，让一个结构化的作用域名字总能变成一个合法的单段目录名，而不是被拒绝。折叠**本身**就是路径穿越防线——`/` 永远活不到路径拼接那一步。
2. **折叠后再用正则校验**是纵深防御。两条规则从同一个字符集常量派生，所以它们不可能漂移成非互逆——而漂移恰恰是唯一能开出洞的方式（校验放行了折叠不再清除的字符，或反之）。
3. **纯点名字单独拒绝**（`.` / `..` / `...`）：正则允许 `.`，若不额外拦一道，一个折叠后的名字仍可能爬出空间根目录。

这个函数是导出的，因为附件放置发生在会话提交时——那时 warrant 的运行时还够不着——而放置目标必须与之后服务这个空间的文件通道**逐字节一致**。

**本地文件通道**（`50-localfs.go`）把每个操作的路径解析到根目录之下，并拒绝任何逃逸：先做词法检查（`..` 与绝对路径通过强制归根被中和），再做**符号链接确认**——词法检查挡不住空间**内部**指向外面的符号链接，而执行通道跟文件通道共享同一个目录，模型完全可以自己造一个。所以它对最深的**已存在**祖先解析符号链接，要求其真实路径仍在真实根之下。

还有一层信息卫生：文件系统错误里嵌着主目录起头的绝对路径，而这些错误会原样流回模型。所以每个返回错误都经过一次改写，只留下空间相对的那一段——模型在空间相对的坐标系里工作，不该学到宿主机的磁盘布局。

**本地执行通道**（`60-localexec.go`）在空间目录里跑 shell。每次执行是一个以空间目录为工作目录的新进程，所以空间里的**文件**跨命令保留（并且与文件通道共享，"先写后跑"成立），但**工作目录与环境变量不跨命令保留**。设计上想要的是一个真正连续的会话，那需要一个伪终端——shell 对着管道会块缓冲，哨兵法会卡死；而对着伪终端的交互式 shell 又带来提示符与回显的处理。所以一次性模型是当前的基线，连续会话是同一个通道接口背后的升级路径。通道本身不管是哪种都被池化——被复用的是持有者。

单次命令有时间上限，产出有字节上限，两者都在通道实现里定死，不由调用方指定。三个要点：

- **环境变量走白名单，永远不用继承来的整个环境。** 这是一条硬不变量：数据库连接串、各类 API key、机器人 token 都从进程环境读，绝不能被一个受模型控制的 shell 继承。只有 `PATH` 与本地化/时区变量透传；`HOME` 与 `TMPDIR` 被钉到空间**之外**的一个私有目录，免得程序的点目录和临时文件污染用户可见的文件区。
- **进程组整体击杀。** stdout/stderr 是管道，等待会一直卡到管道 EOF；一个继承了写端的后台子进程能把整次调用永远挂住，还顺带锁死这条通道上后续的每一次执行。所以整棵进程树放进一个进程组，取消时按组击杀，并给管道 EOF 的等待加一个上限。
- **产出边生成边封顶。** 一条受模型控制的命令可以吐出几个 G；先全缓冲再截断就是一次 OOM。所以用一个带上限的写入器，只保留头部若干 KB 而把总字节数记下来用于生成截断提示，并把尾部不完整的多字节字符切掉，保证留下的部分永远是合法文本。
- **父回合的截止时间先判。** 命令自己的超时上下文派生自回合上下文，所以回合被取消时两者会同时到期；先判回合的那一个，否则一次外部取消会被误报成"命令超时"，把排查引向完全错误的方向。远程通道用同样的判定顺序。

**SSH 执行通道**（`80-sshexec.go`）把命令跑在远端。贵的是 TCP + SSH 握手，所以**连接**被池化复用，每次执行开一个新会话。它是通道池第一个真正有状态的消费者。产出封顶与超时语义与本地通道一致；连接一旦发现已死就自行关闭，让池重建。

发放路径的闸门层次是这样的：`Exec` 先看后端，远程分支先过 `credential:use:<名字>` 这道**二级闸**（针对具体资源），再向凭证代理要连接；本地空间不需要凭证。拿到的通道交给通道池按 (主体, 空间, 类型) 缓存，`Cut` 通过池按主体回收。

### 附件放置

`45-placement.go` 在会话提交时把这一条消息下载下来的附件，从暂存路径搬进已解析作用域对应的**空间**里，这样用户的文件和文件/OCR/视觉工具读取的位置是同一处，并且能活过这一回合。它每条入站消息**只跑一次**（在任何组织内的成员扇出之前），所以一份被多个成员共享的暂存文件只搬一次。

三个细节值得记：

- **入库文件名取自附件的显示名**，不是暂存时那个带唯一前缀的名字。提示词里展示的是这个名字，模型会原样把它传回给工具，所以"显示即磁盘"——不需要每个工具各自实现名字到路径的解析，也不会把暂存前缀泄露出去。显示名不可用时（比如无名贴图）退回暂存名，那个名字本身就是防碰撞的。
- **重名是用创建独占文件来抢占的**，不是先 stat 再写。放置发生在按作用域加锁之前，所以两个并发的同名放置是真实可能的竞态；抢占式命名让它们各拿到一个不同的名字，而不是双双"stat 成功"然后互相覆盖。
- **失败要把路径清空。** 没能放进空间的附件，其暂存路径已经是"空间死"的——留着它会让一个读不到的句柄进入提示词与历史。所以整批放置中止或单条搬运失败时，把路径清掉，降级成"未下载"，而不是留一个假句柄。

搬运优先用重命名，跨文件系统失败时退回复制再删除（暂存区与空间区完全可能挂在不同的卷上）。

### 执行家目录扫除

执行通道用的私有 `HOME`/`TMPDIR` 目录树，用户看不见、模型也看不见——这份隐私是双向的：没人看得见，也就没人会去清理，于是它会在部署的整个生命周期里无限增长。`45-exechome-sweep.go` 是它的保留期扫除，挂在 trunk 的 housekeeping 调度器上（持久化磁盘状态归调度器管，而不是模块自转定时器）。

规则按激进程度排列：

- **孤儿**：对应空间已经不存在的家目录，整个删除。
- **缓存**：活着的空间里，那几个众所周知的可再生缓存目录，其**内容**按修改时间做保留期裁剪。冷掉的缓存下次会重新下载——慢，但绝不会错。
- **临时垃圾**：家目录根就是 `TMPDIR`，所以顶层的非点条目（临时文件/目录）按各自的修改时间整条删除。
- **其余一律不碰。** 各种点目录是**安装状态**：用户级安装出来的树会永远保持安装时的时间戳，按年龄裁剪会把一套还能用的工具链删掉一半——那是错，不是慢。

这棵树是模型可写的，所以遍历全程用固定住的目录句柄，而不是路径字符串。路径字符串遍历会给出一个窗口：在检查与删除之间把目录换成符号链接，从而删掉树外的文件。

### 热重载与撤销

`40-slash.go` 提供三条命令。

`/tools` 与 `/skills` 用**发送者自己的主体**跑一遍和真实回合完全相同的投影，所以列出来的就是他真正能用的那一份，而不是一份另写的"应该有什么"的清单。两条命令都只列名字：描述是写给模型看的工具契约（一段功能性提示词），不是面向用户的文案，展示它等于把一段无法本地化的文本推给用户。这两条命令归 warrant 是因为"按身份投影"本来就是它的本职——塞进会话侧的命令里会让一个层级更低的模块反过来去够目录。

`/skills reload` 顺带做一件必要的事：重扫技能目录之后**立刻对账**，让新扫到的技能拿到自己那一行默认关闭的授权。否则它既被 fail-closed 拒绝、又不出现在权限文件里，管理员根本无从打开它。

`/permission reload` 是管理员动作：重读矩阵文件、按当前目录对账、原子换进活矩阵。子命令是必需的（而不是让裸命令直接等于 reload），这样将来加别的子命令不会改变现有的调用面。

重载与启动的失败姿态**故意不同**：启动时没有更早的矩阵可留，所以必须 fail-closed；重载时手上有一张好的矩阵，所以解析失败就**不换**，管理员保住旧矩阵并看到哪里坏了。

换进新矩阵之后要做**差集撤销**：比对新旧两张表，凡是丢掉了任何一项授权的主体，它手上还活着的池化通道全部回收。否则一次权限**移除**会滞留在一条池化通道上直到空闲超时，甚至挺过一整个进行中的回合。纯增量的重载（对账补出来的默认关闭行、新授予的一项能力）不撤销任何人。按主体撤销是因为池以主体为键；一个仍被授权的通道只是重新获取并重新校验一次而已。

### 运维面

`90-panel.go` 是这个模块对 webui 的自描述，**仅管理员可见**——矩阵是敏感数据，未认证时从状态接口里整块抹掉。面板展示健康状态、主体数、授权总数，以及一张"能力 → 被授予者"的只读表，让管理员一眼审完谁能用什么。

可编辑的那一面是一个 yaml 编辑器，改的就是管理员本来会手工编辑的那份文件。保存前的校验是**严格**的，而不是宽松的解析：一次点击就让新策略上线，而一个拼错的顶层键、或者被清空的编辑器，在宽松解析下会得到一张**空矩阵且不报错**，随后保存动作就会把全实例的授权抹平、把每个主体的通道全部撤销，并报告"成功"。所以拼错的键被严格模式拒绝，空文档被专门的空值守卫拒绝。要真的撤销一切，得手工编辑再走重载——让这件事必须是有意为之。

保存路径把原始文本落盘（保住注释与顺序），然后走与斜杠命令**完全相同**的重载路径。写文件和重载之间全程持有写锁，否则一次并发的重载会挤在中间把这次保存冲掉。

## 设计理据

**授权只有一个真相源：权限配置 + 闸门。** 没有"管理员兜底"这种旁路，也没有任何第二处 `IsAdmin` 判断可以绕过矩阵。任何"临时放行"的口子都会变成永久的口子，而且会让审计日志说谎。

**fail-closed 是姿态，不是异常处理。** 每一处的默认答案都是"不"，而不是"先放行再说"：

| 出了什么事 | 结果 |
|---|---|
| 权限文件存在但解析不了 | 拒绝一切，并在第一次投影时叫管理员 |
| 权限文件不存在 | 空矩阵（同样拒绝一切），对账会把行补出来 |
| 空间配置存在但解析不了 | 空间路由整体停用 |
| 能力目录读不到（空集） | 不剪枝，保住已有授权行 |
| 技能目录降级 | 对账只增不删 |
| warrant 模块自己缺席 | 零工具、零技能 |
| 热重载时文件坏了 | 不换，保住手上那张好矩阵 |

这也决定了模块虽然标着 Optional，缺席的含义却是最严格的那一种。

**判官不解析身份。** warrant 不认识"谁"、也不认识"哪条流程"——它只接受一个已经解析好的 `GrantSet`。这让外层单租户策略与组织内的按公司/角色权限走**同一个判官**，两条路径的过滤语义不可能分叉；也让身份模型将来怎么改，都不需要动授权引擎。

**通道是授权的产物，不是工具的私产。** 工具不自己开文件句柄、不自己起 shell，而是向 warrant 要一条通道。于是"能不能碰"和"怎么碰"分开了：闸在 warrant，机械在通道实现里，撤销在池里。权限一变，回收是一次调用的事。
