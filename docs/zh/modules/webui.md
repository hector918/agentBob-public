# webui

浏览器端的管理面。它本身是一个**通用渲染器**——不认识任何子系统，只把各模块自己注册进来的面板画出来。

---

## 在架构中的位置

**Provides**

| 能力 | 谁在用 |
|---|---|
| `contract.PanelRegistry` | 几乎每个有运行时状态的模块 |
| `contract.TakeoverMinter` | [tools](tools.md)（`escalate_to_coo` 交接给人时铸令牌） |

**Needs**

- `contract.SlashRegistry` — 见 [slash](small-modules.md#slash)。webui 把 `/webui`、`/takeover` 两条命令登记进共享命令表。
- `contract.ClaimTokens` — 见 [claimtoken](small-modules.md#claimtoken)。一次性解锁令牌的生命周期托管在那里。

**软连接（`TryRequire`，缺了就降级）**

- `contract.AdminLine` — 启动时把一枚解锁令牌推给管理通道。
- `contract.BrowserTakeover` / `contract.BrowserControlHold` — 由 [tools](tools.md) 提供，接管端点的后端。
- `contract.SessionResume` — 由 [session](session.md) 提供，人把浏览器交还后唤醒对应会话。

这四项都**延迟解析**：它们的提供方都 `Needs` webui 提供的 `PanelRegistry`，拓扑序必然排在 webui 之后。在 `Start` 里解析只会拿到 nil 并悄悄废掉接管功能；改成首次使用时再取，那已是启动很久之后。

## 功能

**面板注册机制。** 这是本模块对全项目影响最大的一件事，详见下节。

**只读仪表盘。** 一个后台轮询器按固定节拍重新拉取每个面板的 `State()`，把结果发布成一份快照；HTTP 处理器只读快照，从不触发即时轮询。未认证的访问者看到的是删去了 `AdminOnly` 面板的版本。

**一次性令牌解锁。** 没有账号密码。管理员在聊天里执行 `/webui` 得到一枚短时效的一次性令牌，粘进页面上唯一那个输入框，服务端换成一枚会话 cookie。

**唯一输入框（dock）跑命令。** 已解锁的管理员可以在同一个输入框里直接执行斜杠命令，回复被捕获后原地渲染。可执行的命令有一份显式白名单——只收那些「全局、管理向、副作用由参数界定」的命令；依赖聊天上下文的命令（新建会话、查看当前会话之类）被刻意排除在外。

**浏览器接管中继。** 当 agent 撞上登录墙或验证码时，它可以把浏览器交给人。webui 提供实况画面（服务端推送的逐帧图像流）、输入回传、人机控制权的心跳租约、以及「保存登陆」写回。鉴权由 webui 全权负责，浏览器服务本身不认识任何用户业务。

**公开法务页。** `legal/` 子目录里是两份静态 HTML（服务条款、隐私政策），走**免鉴权**路由，供接入的聊天平台与用户直接抓取。除此之外无逻辑。

## 内部结构

### 面板注册表

`10-registry.go` 里的实现只是一张 `id → contract.Panel` 的表，加锁读写，按 id 排序输出。它有意做成 [slash](small-modules.md#slash) 的镜像：

- webui 提供注册表，各模块在自己的 `Start` 里 push 一次；
- 面板是一个**闭包结构体**（`State` / `Read` / `Apply` / `Page` / `View`），闭包捕获的是模块自己的状态。于是 webui 只 import `contract`，一个子系统的知识永远不会渗进渲染器；
- 重复 id 或空 `State` 直接 panic——和 trunk 注册能力时一样的姿态：接线错误必须在启动期炸出来。

这解释了为什么 wantGraph 里那么多模块 `needs contract.PanelRegistry`：目前有十余个 leaf 模块和两个流程各自挂了面板。**每个模块自我描述**，webui 只认一套固定的字段词汇：

| Kind | 渲染成 |
|---|---|
| `stat` / `status` | 一个数值或一枚状态灯（`ok` / `warn` / `down` 着色） |
| `table` | 表格；支持服务端分页、标签过滤、逐行按钮 |
| `text` | 多行说明 |
| `graph` | 节点/边图，按 band 分层；支持水平分带与半圆放射两种布局 |

一格表格 cell 可以携带「为什么」详情、「复制」动作、下钻链接，或一枚**预填按钮**——点它不会直接执行任何东西，只是把一条斜杠命令填进 dock，由管理员过目后回车。写操作因此始终是「预填 + 确认」，而不是隐藏在 UI 后面的隐式副作用。

`Panel.Upstreams` 让每个模块声明自己依赖谁；首页那张依赖图就是把这些自述边拼起来画的——没有任何一处集中维护的拓扑。

### HTTP 层与快照

`20-server.go` 建路由、跑两个后台循环、发布快照。整个 HTTP 面按鉴权分成三档：

| 档位 | 端点 | 说明 |
|---|---|---|
| 公开 | 首页 · 前端脚本 · `legal/*` · 开场文本 | 静态资源与法务页 |
| 公开但会删减 | 状态快照 · 面板分页 · 面板视图 | `AdminOnly` 面板对未认证者整块隐去 |
| 换取会话 | 提交令牌 · 登出 · 查询自身覆盖面 | 「我是谁」只回覆盖面，不回任何身份 |
| 需管理会话 | 面板设置读/写 · dock 命令执行 | 写入面全在这一档 |
| 按作用域授权 | 接管相关端点 | 覆盖面必须覆盖目标作用域；后端缺席时统一回「暂不可用」 |

首页路由被**钉死在恰好一条路径**上。前端没有客户端路由（脚本只请求已登记的端点），所以一个兜底的首页会让每一个打错的路径都返回 200 加 HTML——于是一个敲错的接口地址会以「JSON 解析失败」的面目出现，而不是一个干脆的 404。

轮询是**单个顺序 worker**：某个面板的 `State` panic 了，会被隔离成空字段并记一条警告，不会带走轮询器、也不会跳过后面的面板。这里**故意没有**每面板超时或 goroutine 扇出——一个已经陷进去的 Go 调用本来就无法跳过，只能在另一条 goroutine 上放弃它（那正是早先泄漏的写法）。真正的隔离是**关注点之间**的：令牌与会话的过期清扫跑在自己的 ticker 上，不会被卡住的面板拖住。即便快照停止刷新，HTTP 处理器仍然照常返回上一份缓存，从不阻塞。

启动姿态也是刻意的：webui 是**非可选**模块（别的模块才能硬依赖它的注册表），但它的 `Start` **永不因为端口占用而失败**——监听不上就记一条警告、不服务任何页面，注册表照常提供，agent 继续跑。绑定到非回环地址时会额外告警一次。

### 鉴权与「覆盖面」

`30-auth.go` 的模型只有一个概念：**coverage（覆盖面）**，一个对鉴权模块完全不透明的字符串。

- 覆盖面 `*` = 全局管理会话，能到达每一个写/管理端点；
- 覆盖面为某个作用域 = **能力会话**，只能接管那一个作用域的实况浏览器，够不到任何管理端点。

同一覆盖面下最多只有一枚待用令牌加一个活会话：重新铸令牌是对该覆盖面的**硬重置**（作废旧令牌、踢掉旧会话）。这样一来，鉴权代码里没有任何组织结构或浏览器的知识——它只比较字符串，从不解释它。活跃覆盖面的总数有上限，`*` 永远放行（它是原地重铸），只有新的作用域覆盖面会在撞顶时被拒。

一次性令牌本身寄存在 [claimtoken](small-modules.md#claimtoken) 设施里；webui 只保留一份「覆盖面 → 当前待用令牌」的镜像，用来在重铸时作废前一枚，以及自己持有那些长期的会话 cookie。

### 前端外壳

`40-page.go` 把整个前端（一个单文件脚本）在编译期 embed 进二进制。首页的 DOM 只有两个元素：一张铺满窗口的画布，和那唯一的输入框。所有形态——图层、编辑器、下钻、接管视口——都画在画布上；代码编辑复用同一个输入框（在编辑态长成多行）。

### dock 命令执行

`60-run.go` 把 dock 里的一行合成成一个「webui 来源的管理员私聊事件」，用一个**捕获式 sink**（把回复攒起来而不是投递出去）走一遍正常的斜杠分发，再把攒到的文本连同一个成功/失败标记回给前端。命令白名单在这里，不在前端。

### 接管端点

`70-takeover.go` 是几个把浏览器服务的接管面转发给人的处理器：帧流、输入、控制权开关、保存登陆、以及给管理员用的「谁有活浏览器」列表。每个按作用域的端点先跑一次覆盖面授权（`*` 见全部，能力会话只见自己那一个）。

两处细节值得记：

- **保存登陆前先验持有控制权**。只是围观的人点保存，会把一份没有登录态的副本写回主档——所以未持有控制权时直接拒绝，前端提示进入控制模式后重试。
- **保存与「关掉控制」对交还的判定不同**。关掉控制开关时，只有确实释放了一个活着的租约才算显式交还（租约自然过期不算，否则一次心跳中断会被误读成人已经走了）；而点「保存登陆」本身就是显式交还，即使心跳恰好断了也必须唤醒那个等着的会话，否则人已经把登录办完了，agent 却永远闲在那儿。

`50-slash.go` 是这条路的聊天侧入口：`/takeover` 先确认真有活浏览器再铸一枚作用域锁定的令牌。非管理员限私聊——令牌是随回复发的，发在群里等于泄漏。它还处理一种情况：群里被扇出的成员，其浏览器副本挂在「群#成员」这一层子作用域上，裸群作用域看不见；于是枚举活副本按前缀匹配，并且——**显式点名了某个成员却没匹配上时必须响亮地失败**，绝不能悄悄回落到群作用域，那会发出一枚指向错误浏览器的令牌，而且和一次合法回复逐字节相同。

## 设计理据

**渲染器不认识子系统。** 备选方案是让 webui import 各模块、知道怎么画模型池、怎么画会话。那会让 UI 成为一个反向的依赖汇聚点，并且破坏 leaf 之间零 import 的硬规则。改成每个模块自述后，加一个新面板不需要动 webui 一行代码；而「加一个新的字段种类」才是需要 review 的动作——固定词汇是有意的约束。

**写操作一律预填确认。** UI 上的按钮不携带权限，它只是把一条命令写进输入框。真正的执行仍然走同一套斜杠命令与其自身的鉴权，仪表盘因此不构成第二条权限旁路。

**降级而不是中止。** 端口占用、面板卡死、接管后端缺席——每一种都只让界面变差，从不影响 agent 收发消息。反过来，接线错误（重复面板 id、空 `State`）在启动期直接 panic：那是程序员的问题，不是运行时的问题。

**覆盖面是一个不透明字符串。** 鉴权本可以直接理解「这是一个群」「这是一个成员」，那样会把组织模型抄进 UI 层。改成只比较字符串之后，接管这条能力线可以随时换掉它的作用域含义，而 webui 一行不动。
