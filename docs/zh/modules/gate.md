# gate

进站的第一道闸。每一条从任何平台进来的消息，都先在这里过一次「这个人能不能跟 bob 说话」，然后才有资格进入后面的管线。

---

## 在架构中的位置

**Provides**

| 能力 | 谁在用 |
|---|---|
| `contract.Screener` | inbound 流程（唯一调用方，见 [flows](../flows.md)） |
| `contract.AccessGranter` | [accounts](accounts.md)（身份绑定时顺手放行申请人） |

**Needs**

- `contract.ClaimTokens` — 见 [claimtoken](small-modules.md#claimtoken)。退回通知里那枚准入码在这里铸造与验证。
- `contract.SlashRegistry` — 见 [slash](small-modules.md#slash)。登记 `/gate` 命令；兑付一枚令牌时，也是把令牌携带的那批命令交给这张表去分发。
- `contract.PanelRegistry` — 见 [webui](webui.md)。挂一块面板。

本模块**非可选**：没有筛查，一个受控来源就等于没有授权。所以策略文件加载失败必须中止启动，而不是失败即放行。

只有中枢的 inbound 流程调用它——各个平台接入侧不做提前筛查，即使某些协议天然能更早看到发件人。访问控制统一收在这一点上。

## 功能

**每来源一份访问策略。** 每个接入来源对应一个 yaml 文件，描述：整源开放与否、放行名单、拒绝名单、管理员名单、按群覆盖、以及是否开放入职。文件名就是来源名。**零值即关闭**——文件缺失或加载失败的受控来源一律失败关闭，不会滑向开放。

连接配置（是否启用、凭据从哪来）**不在这里**——那属于中枢配置与来源总线。这份文件只承载访问策略，并且支持热重载。

**三步筛查顺序。** 每条进站事件按固定顺序过闸：

1. **拒绝名单** —— 命中即丢弃，且不回复、不记账（见下）。
2. **裸码兑付** —— 消息正文若整条就是一枚活令牌，它本身就是凭据，越过放行名单。
3. **放行名单** —— 上面都不中时，问策略这个人在这个聊天里有没有资格。

裁决有三种：**通过**、**丢弃**、**已兑付**。「已兑付」是一种特殊终局：事件本身已经被消费掉，绝不能继续往下走，但可能带一句本地化的回执给调用方按自己的平台规矩投递。

**入职开放。** 一个来源可以逐个 opt-in 打开入职：未在放行名单上（且未被拒绝）的陌生人被**放行**到路由，由 intro 流程建一个待批的裸账号。这不是「对所有人开放」，而是「对入职开放」——真正的准入下沉成账号上的授权。默认关闭，所以没有账号体系的部署不会被悄悄敞开。裁决里带一个标记告诉下游「这是入职通道进来的」，inbound 流程据此**不给**这类发件人斜杠命令分叉：一个未获批的陌生人打出的 `/…` 应该走进入职对话，而不是执行一条会改状态的命令。

**退回通知带准入码。** 被闸挡下的陌生人会收到一句友好的说明，里面带一枚**当场铸出的准入码**。这枚码不是权限，而是一批**冻结的命令**——恰好放行「这个申请人、在他被挡下的那个范围」。真正的管理员把它粘出来即可完成放行。它可以安全地出现在公开群里：授予目标在铸造时就被冻死，而不合资格的人拿去兑付什么也提交不了。

首次接触发一次，之后进入静默窗口，窗口过后再来一条——既不会让错过第一条的人干等，也不会让一个话痨陌生人把机器人变成刷屏机。

**被拒名单台账。** 一份有界、去重的内存台账，记录最近被挡下的发件人。它解决的是全新部署时的先有鸡先有蛋：「我需要自己的 id 才能放行自己，但携带这个 id 的那条消息恰好被丢弃了」。管理员在面板上就能看见并一键放行。

**策略写入与热重载。** 放行动作直接改那份 yaml，随后原地热换活策略。webui 面板里也有一个整文件编辑器，保存即重载。

## 内部结构

### 策略模型（`10-policy.go`）

`Policy` 是一个来源的完整访问策略，`Group` 是按群的覆盖。合并规则是显式的两层：

```
被拒（源级 或 本群级）                 → 拒绝
否则 本群 allowlist_add 命中 或 本群全开 → 允许
否则 本群有 allowlist 且不在其中         → 拒绝
否则 源级全开 或 在源级 allowlist 中     → 允许
```

按群的三种放行语义是刻意分开的：`allowlist` 是**收紧**（本群只准这些人），`allowlist_add` 是**并集**（在源级之上额外放这些人），`allow_all` 是**本群全开**（一个整体关闭的来源也能有一个完全敞开的群）。无条件的并集授权检查在收紧的那道之前，否则一份填了内容的按群名单会把它遮掉。

id 匹配是精确字符串比较，只有一个例外：含 `@` 的 id（邮件地址）不区分大小写。邮件侧会把发件人规范成小写，而人手写进 yaml 的地址天然大小写混杂；精确比较在这里会静默失配——放行名单失配是关闭（还好），拒绝名单失配是**开放**（不能接受）。平台 id 从不含 `@`，因此它们的精确比较不受影响。

加载时，**单个文件解析失败是致命的**：与其让一个来源悄无声息地掉回关闭默认值，不如给运维一记响亮的「这个文件坏了」。而一个**拼错的顶层键**（比如把 `allowlist` 敲成别的）不致命——一个笔误不该让所有来源瘫痪——但会记一条醒目的警告，因为它同样会让这个来源意外地关闭。

### 筛查器（`30-screen.go`）

`Screener` 的实现：持有可热换的策略表、令牌设施、被拒台账。策略表整张原子替换，所以重载对并发的进站事件是无缝的。

拒绝名单命中时**不进台账**。台账是给全新部署做「发现陌生人并放行」用的，而被明确拒绝的人恰好是它的反面：记进去会污染这份有上限的台账、把真正需要的 id 挤老，而且面板上那个「放行」按钮对他们本来就是空动作（拒绝优先于一切）。

铸退回码时会**顺手作废它替换掉的那一枚**：每次重新触发都会铸新码，不这样做的话一个话痨陌生人会攒下一串同时有效的令牌。同一个（来源, 聊天, 用户）上最多留一枚活码，而且这枚码的有效期很短——一枚活的授权码不该在世上躺好几天。

### 批命令兑付（`36-batch.go`）

一枚令牌携带的不是权限，而是**一批命令**。兑付时逐条走正常的斜杠分发，回复被一个捕获式 sink 收进一份回执。

关键的三条：

- **权限来自哪里。** 每条命令以「令牌自带的权限 或 兑付者的**真实**管理员身份」执行。真实身份在这里现查，因为事件上的管理员标记要等筛查返回之后才盖。于是一枚非管理员的退回码只有在真管理员手里才跑得动它那条管理员命令；而一枚管理员铸出的、明确标了「以管理员身份执行」的码，则对持有者生效（持票即预授权）。
- **不合资格的兑付保持惰性。** 申请人自己把自己的退回码粘出来，什么也提交不了；此时**不发回执**，直接落回正常筛查（令牌留着、人照常被挡）。发一份回执等于给出一个「这枚码是活的」的探测器。
- **全成才烧。** 只有整批都成功才消费掉令牌；部分失败保留原有效期，让兑付者重试——批里每条命令都是幂等的（放行是空动作、审批不覆盖），重跑只会补上失败的那一步。

每条命令的分发都有一个超时。兑付跑在**单条进站消费循环**上并同步做存储/文件 I/O，一次挂死的往返会把所有进站消息堵在队头。

### 策略写入（`50-write.go`）

`AccessGranter` 的实现。两条写路径：源级放行，和按聊天的并集放行。两者都是「读—改—写」加原子落盘，并由同一把锁串行化。

写入是 **yaml 节点级的外科手术**，而不是把类型化的 `Policy` 反序列化再序列化回去。理由是后者会静默丢掉结构体没建模的一切——尤其是按群配置下的自定义键。节点手术只重写目标那一段序列，文档其余部分（嵌套的群配置、未建模的键、注释）逐字保留。

几处细节：

- 写进去的**用户可控值一律加引号**。一个恰好长得像 yaml 字面量的 id（纯数字、或者写成 `true`/`null` 的样子）不加引号会在下次加载时回来成一个类型化的标量，那条记录就静默消失了。结构性的键保持裸写。
- 空白的 `allowlist:` 是一个 null 标量而不是序列，往它的内容里追加会被序列化器悄悄忽略——所以先就地升格成空序列。
- **拒绝名单优先于放行**：给一个被拒的人写放行行会写出一条自相矛盾、且筛查根本不看的记录，还会报一个假成功。这里直接拒绝，并用一个专门的错误值让上层能说清「先把他从拒绝名单里拿掉」。
- **「已经在里面了」不算终局成功**：之前可能有一次写入落了盘但热重载失败（加载是全有或全无，一个坏掉的兄弟文件就能让它失败），活策略因此是旧的。所以这条路径上照样重载、照样清台账。

面板的整文件保存和这条外科路径共用同一把锁——原子重命名只防半截文件，防不住丢失更新。

### 被拒台账（`20-rejected.go`）

有界、去重、并发安全。淘汰按**首次出现**时间而不是最近出现时间：后者会让一个反复被拒的噪声源不断刷新自己而把自己钉住，同时把那个只出现过一次的、运维正要找的引导 id 挤掉——刚好和这份台账的用途相反。

放行之后台账行会被清掉。源级放行清掉这个人在**所有**聊天里的行；按聊天的放行只清那**一个**聊天的行，这样一个在多个群里被挡的人，在其余群里仍然排在队列上等着。

### 模块装配与面板（`40-module.go` / `90-panel.go`）

模块把上述部件接起来、提供两项能力、登记 `/gate` 命令、挂上面板。

`/gate` 有两种形态：源级放行，和按聊天放行。面板上每一行「放行」按钮预填的形态**与这个人被挡下的位置一致**——群里被挡的人预填按聊天的形态，不会顺手把他在这个来源的所有聊天里都放行掉。和令牌路径同样的收敛口径：一键放行绝不比令牌授得更宽。

面板另有一份「每来源一个 yaml 编辑器」。保存时的校验有意用**类型化的结构体**而不是松散的字典去反序列化：一个类型不匹配的值能骗过字典探测、被提交下去，然后在**下一次启动**时让加载失败——而 gate 是非可选模块，那等于整个进程起不来。

## 设计理据

**关闭是默认值，而且是零值。** 一个 Go 结构体的零值就是「谁也不许说话」。这样一来，任何一条「文件没有 / 解析失败 / 键写错了」的路径都天然落在关闭那一侧，不需要额外记得写一句检查。

**准入码是一批命令，不是一份权限。** 备选设计是让令牌携带「某某权限」，兑付时授出去。改成携带一批**冻结的命令**之后，令牌的能力上限在铸造那一刻就写死并且完全可读——而且兑付走的是和管理员平时一模一样的斜杠命令与其自身的鉴权，没有第二套授权逻辑需要单独审。

**发现优先于配置。** 被拒台账严格说不属于访问控制，它属于**可运维性**：没有它，一次全新部署的第一步就是去日志里 grep 自己的 id。它有上限、会淘汰、重启即空——刻意做成了一份易失的引导辅助，而不是一份记录。

**筛查只做访问轴。** 「这个人能不能说话」和「这个人的账号被批准了没有」是两件事。gate 只管前者；后者是下游账号上的授权。入职开放这条通道正是把两者拆开的产物——放行名单退化成一份花名册，拒绝名单仍然是硬阻断。

**策略是文件，不是表。** 访问策略留在磁盘上的 yaml 里而不是数据库里，代价是写入要自己做原子性与串行化，收益是运维可以在没有 bob 参与的情况下直接读、直接改、直接备份——包括在 bob 因为策略写坏而起不来的时候。写路径因此被设计成外科手术式的：它必须能在一份人手编辑过的、带注释和未建模键的文件上安全落笔。
