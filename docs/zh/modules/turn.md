# turn

turn 是回合执行机制：拿到一份流程组装好的 `TurnSpec`，把**一个**有界的回合从头跑到尾——读历史、拼消息、调模型、把回复流到 sink、把交换过程落库。它对是哪个流程驱动了它一无所知。

---

## 在架构中的位置

**Provides**：`contract.Turn`——只有一个方法 `Run(ctx, TurnSpec) TurnResult`。

**Needs**：`contract.MessageStore`（由 [session](session.md) 提供并拥有）· `contract.ModelPool`（由 [model](model.md) 提供）。

turn 不直接碰数据库。它唯一的数据库用途就是历史，而历史归 session——所以这里只剩一条通过契约接口的消费边。`MessageStore` 是**硬** Need：没有历史就没有有意义的回合。反向那条边（session 需要有人真的跑回合）是软的、懒解析的 `TurnHandler`，对拓扑排序不可见，所以图仍然无环。

**上游**：[flow-normal / flow-agora](../flows.md) 组装 spec 并驱动核；[session](session.md) 的仲裁器决定何时轮到这个回合跑。
**下游**：[model](model.md) 的模型池（对话、流式、分词、窗口）；spec 里带进来的工具集、技能集、通道与凭证开启器（由 [tools](tools.md) / [warrant](warrant.md) / [skills](skills.md) 经流程投影后交进来，turn 只调用，从不裁决权限）。

`TurnSpec` 的分工线很清楚：**流程组装 spec，turn 拥有其余全部**。特别地，`Prompt` 交进来的是**构造器**而不是构造好的字符串——核每一轮重新 Build，所以多轮回合会自动带上增长的历史和本轮的瞬时层。

---

## 功能

- **一个回合的完整生命周期**：先落用户行，再进入轮次循环（模型 → 工具派发 → 再来一轮），最后经某扇「门」收尾，向 sink 恰好 Finish 一次。
- **两个循环驱动**：`regular`（预算受限的答复循环）与 `looping`（收敛驱动的工作循环），共享同一个轮次内核与同一族护栏。
- **工具轮**：并发派发（可退出并发）、结果管道（脱敏 → 截断 → 摘要 → 空值兜底 → 落库重试）、孤儿修复。
- **上下文压缩**：滑窗切段 + 逐段摘要 + 合并，触发与切分都用**称重制**（后端分词器的精确计数）。
- **打捞（salvage）**：一个跑干了预算或撞上护栏的回合，仍然欠用户一句可读的话——阶梯式地把它挣出来，而不是发一句道歉模板。
- **退化检测**：小模型掉进重复墙时，在流中就中断，并让被污染的历史在每次重建时自愈。
- **护栏与进展谓词**：同调重复、单工具连败、无进展预算，全部按**陈旧度**而非轮次计数。
- **验收闸**：技能自带的 RUBRIC 机械校验，以及 looping 模式内置的顾问复核。
- **子循环委派**：深度 1、阻塞、串行的子回合，跑在干净的上下文里，只把产物交回。

## 内部结构

### 一个回合的生命线

```
Run
  ├ nil-sink 检查 · panic 兜底
  ├ 先落用户行（每个说话人一行，原子批）
  └ 按 Mode 派发一次 → 驱动的循环：
        循环顶  压缩（称重触发）→ 武装回读工具 → 机械 nudge 阶梯
               → 用户 nudge 快车道 →〔looping：停滞诊断〕
        一轮    重建提示 → 通告工具 → 一次流式模型调用
               ├ 无工具调用 → 最终回复门 →〔验收闸〕→ 落库 + Finish
               ├ 有工具调用 → 落助手行 → 派发 → 结果管道 → 继续 / 退出
               ├ 超窗       → 强制压缩 → 重试本轮
               └ 退化 / 膨胀 / 取消 / 断流 → 各自的门
  共享收尾   预算跑干 → 取消门（静默）→ 打捞
```

循环顶那四步的**顺序**是有理由的：压缩必须在本轮读历史之前（它顺手把读到的回放交给这一轮复用，一轮因此只读一次历史）；回读工具的武装必须紧跟压缩（压缩写入后会重读一次，好让同一个循环顶就武装到新鲜的摘要上）；停滞诊断放在 nudge 阶梯**之后**，这样一个已经要在预算护栏上退出的回合，不会去买一份它根本用不上的咨询。

### 外壳：一次 Run 的骨架

`Run` 是所有驱动共用的外壳，只做四件事：

1. **前置检查**：没有 sink 的 spec 无法投递回复——返回一个受控错误，而不是在轮次深处 nil-panic。
2. **panic 兜底**：轮次路径上任何未捕获的 panic 都不能让用户面对沉默——带栈记日志、Finish 一句通知、把错误带回去。
3. **先落用户行**：在调模型**之前**写。每一轮的消息列表都完全从历史重建，所以这一次写失败就意味着模型永远看不到用户刚说的话——它会对着陈旧历史静默地答错。所以这里失败就诚实中止。（若中止的原因是 context 已被取消，那不是存储故障：静默退出，但仍然释放 sink。）
4. **模式派发一次**：`spec.Mode` 在这里被读取，**且只在这里**。轮次内核与整族护栏永远不读它——它们是所有驱动共享的节奏不变量。未知模式一律走 regular（保守失败，绝不进半成品路径）。

驱动返回 `(结果, done)`。`done=false` 时落回外壳的共享收尾：默认的「跑完预算」出口 → 取消门（静默）→ 打捞。

### 两个驱动，一个内核

这是本模块最核心的一条设计：**绝不按 Mode 分支**。两种退出语义是两个**策略**，各自一个文件；轮次内核、护栏、压缩、称重、结果管道全部单份共享。

| | `regular` | `looping` |
|---|---|---|
| 设计中的正常出口 | 一次最终回复 | 一个**收敛的产物**（模型声称完成 + 已武装的验收闸通过） |
| 轮次预算 | 合法出口——跑干了就打捞出一个诚实的答复 | 退化成**保险丝**——撞上它是病态，不是正常结局 |
| 默认上限 | 40 轮 | 500 轮（保险丝） |
| sink 策略 | 直接流式渲染 | **安静**：内容增量全丢，只有 trace 透传，收敛的产物一次性 Finish |
| 顾问 | 无 | 内置（停滞诊断 + 交付前复核） |

两个循环的骨架故意长得几乎一样。这是隔离的代价也是隔离的目的：`looping` 的退出语义可以继续演化，而 `regular` 永远看不到那些 diff。

安静 sink 还额外**扣住图片**：一个工作回合跑几分钟，每一步的图流出去就是刷屏——所以图全部扣到回合结局落定后一次性放出，包括被验收闸打回的那几次尝试（没有眼睛的人分不清模型的第三稿和第一稿，那是用户自己的判断）。放图在两个点做（Finish 与驱动的延迟释放），两个都幂等——因为打捞和循环顶的取消门是在**原始** sink 上收尾的，永远走不到包装层的 Finish；而 panic 是任何显式钩子都覆盖不到的那一个。

### 轮次内核

一轮做的事：重建提示 → 通告本回合已授权的工具规格 → 一次流式模型调用（内容边流边渲染） → 分流：没有工具调用 → 最终回复门；有工具调用 → 工具分支。

流式观察器同时干四件事：

- **只在还没冒出工具调用时**把内容转发给 sink——一旦模型开始调工具，之前的文本就是前言，不是用户可见的回复。
- **明文工具标记的截流**：一部分本地模型把工具调用当**文本**吐出来（池要等流关闭后才抽取），不拦就会把整段标记原样流给用户。而且标记可能**跨增量劈开**——所以要把「尾部还可能长成标记的那截」按字节精确地扣住，等下一个增量把它证伪（冲出去）或坐实（丢弃）。
- **思考走 trace 通道，永不走内容通道**：思考是过程不是产物。这也决定了它的全部去向——scope 的 trace 开关关掉时它在 sink 契约处被丢掉，它不进 `Finish(full)`，因此不落回复、不落历史、不进下一轮上下文。推理是一 token 一个事件推过来的，而 trace 每次调用都换行，所以按**句子边界**冲刷，否则就是一行一个词。产物被缓冲的回合（验收闸未判、或安静驱动）里，思考会被额外标记为草稿——一份还可能被推翻的中间读数，绝不能被误当成最终答案。
- **重复墙检测**：内容和思考**各自**按字节计数独立扫描。只扫内容会对「还没吐出一个字就先在思考里循环」完全失明——推理增量算活性，于是那种跑飞会一路跑到供应商的硬超时。

流之外的异常各有各的门：取消（已有可见内容 → 落库 + 一个诚实的「到此中断」标记；什么都没显示 → 完全静默）、流中断（同上，但保留用户已经看到的半个答案，而不是被通知覆盖掉）、参数膨胀中断（分块重试阶梯）、上下文超窗（强制压缩后重试本轮）。

**结束纪律**：每一扇门都必须经 `finalizeTurn`（落助手行 + Finish）或 `releaseSink`（`Finish("")`）收尾，sink 恰好被释放一次。`finalizeTurn` 落库用的是**耐久 context**——回合的 token 可能已经在某次多秒的判官调用中死掉了，但落库与投递必须一致，不能留历史空洞。它还把 Finish 的错误**返回**：投递彻底失败的回合不能被记成一次满意的答复，否则下游会把一次幻影「已回答」入账，永不重发。

**Sink 契约**是很多细节的来源：`Finish` 的 full 必须逐字节延长已经发出的那些内容增量。所以内核精确记账「已经流出去的字节」，最终回复门在流过的情形下用**流过的原始字节**（不 trim）加上未流出的页脚来组成 Finish 文本；而落库的那一行仍是 trim 过的回复（前言已经随它自己那一轮的助手行落过库了，再落一次就是历史重复）。声明自己是「裸产物」的 sink（子回合捕获、跨 agent 返程、邮件攒批）走另一条：它们的 Finish 就是产物本身，绝不能粘上前言。

### 工具轮与结果管道

顺序是固定的，不可跳过，属于机制而非策略：

```
去重 + 补 id + 中和畸形参数 → 落带调用的助手行 → 派发 → 脱敏 → 截断 → 摘要 → 空值兜底 → 落结果行（一次锁重试）
```

几处刻意的取舍：

- **助手行在派发之前落**。派发中途崩溃时留下的是可修复的痕迹；反过来先派发就会留下没有父行的结果行——那是**反向孤儿**，只能向前修复的孤儿修复救不了它，而严格模板会在回放时直接拒绝整个请求。所以这一步写失败就不派发，中止。
- **补出来的合成 id 必须在整个回放窗口内唯一**，不只是本轮内——孤儿修复只认 id，重复的 id 会让上一轮的结果行遮住这一轮的孤儿调用（正是那个修复要闭合的崩溃缺口）。id 里带时间成分，因此重启后铸的 id 也和它要修复的持久孤儿区分得开。
- **畸形参数就地中和成 `{}`**：一个被截断的参数 JSON 会被原样落库并**在此后每一轮回放给每一个模型**，严格服务端直接 400——于是一个坏调用毒死整个池对这条会话的所有后续。中和之后，工具自己的必填检查会返回一个模型能重试的干净错误。
- **先脱敏后截断**。截断在前会让跨越边界的凭证保住未脱敏的头部（脱敏的最小长度锚点匹配不到被切断的尾巴）。而且脱敏必须发生在摘要之前——摘要模型可能在远端，原始密文不能上那条线。
- **摘要只对超阈值的成功负载做**，且工具可以声明退出（逐字工具如读文件、打补丁）。任何失败或空摘要都退回逐字内容——绝不产生空结果或丢结果。

派发默认并发（有上限），声明需要串行的工具在并发批之后单独跑。已被取消的回合不再派发新工具:有些有副作用的工具根本不看 ctx，没有这道闸就会出现「用户取消之后消息才发出去」。所有的 trace 行——调用前一行、结果后一行——都由**主 goroutine** 按调用顺序发出，所以并发工具的输出永远不会交错。

`buildMessages` 每轮重建，并在此处做三次窗口修复：把退化的助手行在**回放切片里**（不是 store 里）换成标记，让已经被污染的历史每次重建都自愈；丢掉被尾部切断的**反向**孤儿工具行；给没有结果的助手调用**向前**补一条合成结果——措辞刻意不断言失败，而是说「可能已经完成，不要盲目重试」，否则模型会把一个有副作用的调用再发一遍。

### 每回合状态

一份纯私有、随一次 `Run` 生灭的结构：退出标记、累计用量、跑过的工具名、折进来的用户 nudge、两条进展水位线（**进展** vs **产出**）、护栏计数器、膨胀阶梯、副作用失败台账、验收闸的武装与重试计数、以及「已经流出去的确切字节」。

退出状态是**标签**不是分支键——驱动唯一分支的只有「是不是取消」（静默）与「其余」（打捞）。零值槽刻意留给「未设置」：曾经取消占着零值槽，于是任何忘记赋值的出口都会读成一次静默取消——跳过打捞、什么都不给用户。现在它落进默认分支，吵闹而不是沉默。

对外，详细的内部退出原因被映射成一个 `TurnOutcome`：`Final`（干净答复，唯一算「被满足」的）· `Process`（刻意的非答复：提问澄清、移交、保持沉默）· `Degraded`（尽力而为的放弃）· `Cancelled` · `Error`。这个分类是跨层决策的第一等信号：哪个闸适用、流程算不算满意、失败学习喂不喂、委派的父级看到什么。

### 进展谓词与护栏

进展的定义是**新信息**：一次成功的工具调用，其结果哈希与该工具上次不同 → 进展；一个声明自己是投递类的工具成功 → 产出（也算进展）。护栏三条：连续相同的成功调用（模型在原地打转）、单个工具的连续失败（换参数轰炸同一个坏工具也算）、以及无进展预算耗尽。

整族护栏与整条 nudge 阶梯都按**陈旧度**（距上一次水位线推进的轮数）而不是原始轮次计数——这正是它们能被两个驱动原样共享的原因：一个还在持续产出的回合无论跑多深都不会被催，一个停滞的 looping 回合无论保险丝多大都会在同一个陈旧度上死掉。

副作用工具的失败单独记账（按「工具名 + 参数」，同一调用后来成功则销账），残留的会变成回复末尾一句诚实的页脚——正面顶住一句声称「已经发出去了」的回复。

### nudge 体系

两种 nudge 都在循环顶施加，但它们是**不同种类的东西**，不再共用一条通道：

- **机械 nudge**（陈旧度阶梯：换个思路 → 停止调工具、诚实作答 → 无进展菜单 → 宽限后退出）是机器生成的引导文本，走一个瞬时提示层，从不落库。全部包在「内部 — 不要引用进回复」的标记里，免得小模型把它原样粘进用户可见的回复。
- **用户 nudge**（忙时到达、被快车道拉进来的那条人类消息）是对话**内容**：它被落成一条真实的用户行，然后拼进本轮的回放，从而以「对话里最新的一条用户消息」的身份抵达模型。

后者曾经也走瞬时提示层，两个毛病叠加：**位置**——人类的问题坐在模型读作背景的地方，和「别中途停下」的纪律层、和一屏工具输出竞争；**无记录**——它没进任何存储（排队消息本来就不写 WAL），而队列侧已经把它取走了，于是模型只要不理它，这条消息就被彻底销毁。落库同时修好两半。

### 路由标签与缓存亲和

每一轮的模型请求都带上会话 id 作为**亲和键**：池因此倾向于把这条对话继续留在上一次服务它的后端上（跨轮、也跨回合，池按键记忆并带 TTL）。它只是负载均衡的 tie-break，永远不会压过故障转移或在等价对等体之间的铺开——但对前缀缓存而言，这一条 tie-break 就是命中与不命中的差别。

工具轮还会**并上**（而不是替换）两个软标签：一个偏好工具调用稳定的模型；本回合失败累积到阈值后再加一个偏好更强的模型。都是软偏好——标签不存在就只是不起偏置。这里也用陈旧度语汇（「距上次进展的失败次数」），所以一个后来恢复的长回合会把这层偏置**卸掉**，而不是背着它跑完一生。

拼标签时会先克隆再追加：请求里的偏好切片与流程持有的那份共享底层数组，裸 append 可能写进流程拥有的数据里——路由标签绝不能改动上游的切片。

### 用户可见的通知与语言

核自己渲染的那几句话（模型不可用、上下文太长、落库失败、内部错误、取消标记、断流标记、打捞兜底）走 i18n 目录，语言取流程在入站时解析好的回复语言；流程没给就从用户输入现场检测。核不为此新增契约字段——用户刚发过来的那段文字就是我们已经握着的、最诚实的信号。

### 验收闸

两个闸，同一次交付上**二选一，绝不并存**（一份产物由两套标准判，成本翻倍还可能出两个判词）。

**RUBRIC 闸**：模型用 `skill_view` 读了某个自带校验准则的技能，就等于说「我在用这个技能」，于是该技能的准则被武装。最终回复门上，一次 LLM-as-judge 调用（路由到带 `judge` 标签的模型）对着证据判产物；判不合格就带着批评重来（有上限），上限用尽则声明失败而不是投出没有依据的产物。判官**只**核对产物与本回合已有的证据是否相符，它无法判断证据本身对不对——准则里就是这么写的。武装是每回合的，不落历史，所以压缩不会把它解除。

一次盲判不合格会**升一档**：在顾问底盘上跑一次有证据能力的第二意见（深度 1 子回合、共享父对话历史），它的判词**覆盖**盲判——可以推翻一次误杀，也可以给出有记录支撑的确认。通过与放行从不升档（一次判官打嗝不该买一个 10–100 倍的子回合），所以便宜的路径仍然便宜。每回合最多升一次。

**顾问复核**：在 looping 模式下、没有 RUBRIC 武装、且这个回合**真的在对话之外改变了什么**（有投递类或副作用类工具成功过）时，交付前由顾问验收。它跑在同一个子回合底盘上，读得到父对话的完整记录，用来核对产物里的关键声明是否真的有据。判词是同一套 JSON 契约，所以三个角色（盲判官、升档裁定人、验收人）共用一个解析器。

两个闸都**判不了就放行**：顾问不可用、判词解析不出来，都记日志 + trace 并通过——一道闸绝不阻拦它没能验证的东西。但复核用尽重试后仍有异议时,异议会作为页脚随产物一起交付,而不是悄悄消失(产物已经存在,宣布失败本身就是另一种谎)。

顾问在 looping 模式里还有第二个身份：**停滞诊断**。陈旧度恰好达到某个值时触发一次咨询（恰好匹配，所以每一段停滞只烧一次），顾问读完完整记录后给出的方向被停进一个专用提示层，管到下一次诊断覆盖它为止。触发权在 harness 手里——「停滞了几轮」是模型看不见的 harness 事实。诊断简报刻意很薄：只带 harness 知道而模型不知道的两个数字（陈旧度、距上次进展的失败次数），因为顾问自己会去拉轨迹，而一份转述的摘要恰恰就是这个回读要绕开的偏见。诊断简报里**不含验收准则**——诊断会被逐字引进被评判模型的提示，把准则折进去等于绕一圈把评分表递给了考生。

到了阶梯的「停止调工具」那一档，停在提示里的诊断会被清掉：harness 已经裁定这个回合停止工作、开始作答，而诊断说的是相反的话，且它在提示里的位置更靠后，会读作更新的指令。

### 压缩

分成两层，中间是一条硬契约：

- **上游只管结构**：切线落在哪里（保住约 budget/3 的最近尾巴，且绝不切开「助手调用 → 工具结果」这一对），以及结果怎么落地（一行摘要标记 + 按形状重新追加的尾巴，一个原子批）。它不越过保留走做任何尺寸推理，也从不因为内容而拒绝。
- **下游只管压缩**：给任意大小的文本，跑**一遍**——在逻辑边界上滑窗切段、每段一次摘要调用、拼接，拼接结果若能装下窗口再加一次合并调用（跨段去重）。拼接后仍然超窗就**原样返回**：它会作为摘要行落地，而摘要行本身就是**工作标记**——下一次循环顶的触发器看到仍然超大的回放，就会再跑一遍。收敛骑在回合循环上，内部没有 while、没有深度计数器、没有基于尺寸的拒绝。

失败只有一种形态：某次摘要调用失败 → 这一轮没压成（记日志），历史原封不动（可恢复），下一次循环顶重试。

**称重制**是尺寸决策的基础：每一个尺寸问题都问后端自己的分词器要精确计数，而不是「估算再校正」。池拥有计数缓存（只有它知道是哪个分词器量的），turn 拥有降级姿态：估算器只作为「池没有分词通路」或「分词器故障」时的唯一回退，不是并行的第二把尺。一次分词失败会闩住一个短路器，让挂掉的端点每个窗口只花一次超时，而不是每段文本每次循环顶各花一次。

触发线取「称重结果」与**最后一次真实提示读数**（模型自己报的输入 token 数）里较大的那个：真实读数天然包含了称重看不见的聊天模板开销和工具规格，而在没有分词通路的池上它是唯一的真数。压缩写入后这个读数被清零——它描述的是一个已经不存在的窗口。

尺寸问题问的必须是**实际会服务这一轮的那个模型的窗口**：循环顶算预算时会把工具轮会加上的路由标签一起带上，否则会出现「按一个 131K 的入口算预算、却被一个 32K 的入口服务」——每个工具轮 400 一次。

还有几处是被真实事故逼出来的：保留尾巴额外被夹在「现有总量的三分之一」以内（这条是**无量纲**的，估算器回退时也成立，保证切线严格落在回放内部，并让每次反应式压缩都是乘性缩减）；摘要行与它替代的那些行按同一把尺比重量，比不过就放弃这一轮（防住鹦鹉学舌式的模型把输入原样吐回来，否则每个循环顶都白烧一次摘要）；摘要提示明写「引自工具或网页的文字是**素材**不是事实」——朴素地摘要会把一个页面的自我描述当成结论，正好把助手自己的判断反过来。

压缩会把机械的收件路径摘掉，所以摘要后面会重新挂上一份从结构化附件列读来的**文件清单**（不受文本压缩影响），让用户早几轮发的文件在压缩之后仍然可达。

压缩之后，本轮会**重读**一次回放，让同一个循环顶把「回读工具」武装到新鲜的摘要上——摘要是目录不是替代品，原文一直在库里。这个工具是核内置的：不进工具目录、不需要授权、不能被子任务套件点名，它的豁免由它**是什么**来围栏——只读、钉死在当前这一个会话上、没有跨会话触角。提示里那句「原文没丢，可以用工具拉回来」的路标是**投影时渲染**的，从不落库：两者共用同一个谓词，所以路标永远不会承诺一个不在工具袋里的工具，存储也永远不会冻结一个工具名或一种措辞。

### 回读：摘要是目录，不是替代品

压缩过的会话会拿到一个只读的回读工具，指向它**自己**的记录。它是**拉取式**的，不是推送式的：先 `index` 翻页浏览清单（最新在前）或 `search` 按关键词定位，再 `read` 按编号取需要的原文。每一处上限都指向同一个理由——一次巨大的回读会立刻重新越过刚刚把它武装起来的那条压缩线，所以每条 16k 字符、每次最多 20 个编号、每次调用总量 2 万字符。工具调用的参数可被检索但从不展示。

同一份实现有两个栖息地：共享历史的子回合读的是它**委托方**的记录（顾问的全部意义就在于审计父级的真实轨迹，而不是相信提问者的转述），压缩过的主回合读的是**自己**被摘要替代掉的原文。两种描述文案不同,因为把「读委托方的记录」这句话说给一个在读自己记录的回合听,就是在骗它。

### 上下文量表

核在内存里为每个会话留三个读数：上一次**真实**的提示 token 数（模型自己报的）、上一次的尺寸预算（会服务它的那个入口的声明窗口）、以及上一次回放窗口里的消息条数。它经由一条软缝暴露给只读面板（`/session`），一次互斥锁加一次 map 读，不碰存储也不碰池。

压缩之后 token 读数被清零而预算保留——前者描述的是「这一顿吃了多少」，那顿饭已经不存在了；后者描述的是「锅有多大」，锅还在。整份表是进程生命期的、有条数上限的：溢出就整表清掉，活着的会话下一轮从模型报数里重新学。

### 打捞

一个跑干了轮次预算、或撞上护栏的回合，仍然欠用户**一句**可读的话。打捞是那句话的来源，跑在自己的短超时 context 上（回合的 token 可能已经死了，而这一句必须落地）。

阶梯：

1. **一次不带工具的模型调用**——模型读这个失败回合的历史（含所有工具结果），从已有的东西里诚实作答。这就是全部价值所在：一句真实的「我查到了什么、卡在哪」，而不是一句道歉模板。退化路径额外先试一档强模型。
2. **不调 LLM 的行动简报**——模型也不可用时，至少把这轮跑过的工具报出来。
3. **固定兜底句**。

打捞之前会把所有**引导性瞬时层**清掉（机械 nudge、膨胀提示、验收重做批评、顾问诊断）。顾问诊断是其中最响的一个：它说的是「接下来该试什么」，和打捞的「别再调工具、就手上这些诚实作答」正好相反；而触发诊断的停滞路径与最终走进打捞的是同一条路，所以这个冲突是常态不是边角。

被 RUBRIC 武装过的回合，即使走到打捞也不能交出一份**没判过**的产物——准则的全部意义就是那条依据保证，而打捞恰恰是最容易编造的一条路。所以第一档的产物照样过一次判（只判一次，没有重试；只判**模型产出**的那一档，下面两档自明地不是产物，没有可编造的东西）。判不过就撤回产物、换上诚实的失败通知——但被撤回的那份原始产物会随结果带出去，好让失败学习反思真正有缺陷的输出，而不是反思那句道歉。

### 子循环委派

原语是「跑一个阻塞的、有界的回合，把它的产物捞回来」——**没有抽核，没有重写循环**。子回合是同一个 turn 核在一个子 sid 上重新实例化，父级的通道/scope/身份靠**传下去**继承，所以子回合零额外权限。这是整个设计的承重墙。

委派不是并发原语。它的回报是**上下文洁净**：父级的历史里只留下任务简报和产物，DOM、图片字节、中间步骤永不进父上下文。

- **深度 1 是硬规则**：子回合里的工具拿到的是一个会拒绝的 runner。
- **私有内存 store**：子回合的转录是它自己的多轮工作记忆，父级只取最终产物，而子回合有界且不可恢复——所以它活在进程内存里，一次硬崩溃丢掉它时**零孤儿行**。这个内存 store 精确镜像持久实现的回放/压缩语义，共享的轮次循环在子回合上因此行为一致。
- **套件围栏在派发层**：模型选的是一个套件**名字**，不是自由的工具列表（少一个注入面）；套件与父级已授权工具求交，套件里父级没被授权的名字就是不存在。会结束回合的「过程类」工具被剔除——子回合没有向用户提问或移交的通道，它必须永远返回一个产物。
- **捕获 sink**：什么都不外流。在子回合里投递文件会**失败**并明确报错（而不是静默丢弃），好让模型把产物折进自己的回答，而不是相信文件已经送出去了。
- **诚实的部分产物**：子回合跑干了轮数或撞上护栏时返回的仍然是文本，但会被标成 partial，绝不冒充干净结果。子回合的 panic 变成一个错误产物，永远不会把父回合带崩。

顾问的三个角色（诊断、复核、升档裁定）全部跑在这同一个底盘上，只是换了 guide 和硬标签；共享父对话历史的子回合还会被**直接注入**回读工具——能力和它的访问工具必须同行。

## 设计理据

### 一个内核，两个驱动

「回合」这个词底下其实是两种目的完全不同的东西：一次聊天答复，和一段可能跑几分钟的工作。它们的差别只在**退出语义**上——预算是合法结局，还是保险丝？

于是分歧被压缩成一个维度：两个驱动文件，各自持有自己的退出语义；其余全部单份共享。`spec.Mode` 在核的入口被消费**恰好一次**，此后没有任何地方读它。这条规则是可执行的判据，不是风格偏好：一旦某个护栏开始问「我现在是什么模式」，两套语义就会渗进内核，而内核是这个模块唯一有能力保持不变量的地方。

它的直接受益是那族按**陈旧度**而非轮次计数的护栏：因为不区分模式,一个 500 轮保险丝的 looping 回合和一个 40 轮预算的 regular 回合遵守完全相同的停滞纪律,只不过前者在持续产出时可以合法地跑很深。

### 回合模式在会话出生时盖章

模式是从 scope 的默认值**盖到会话上**的，并且终身不变。翻转 scope 默认只影响未来的会话。这样没有任何一段对话会在中途换驱动——中途换驱动意味着同一段历史的前半截按一套退出语义写就、后半截按另一套读，而这两套对「跑到预算」的解读恰好相反。代价是「已改但未生效」这个状态，`/session` 把出生盖章和 scope 默认并排显示，就是让操作者看见它而不是去猜。

### 诚实高于安慰

这条贯穿全模块：打捞的第一档是**一次真的模型调用**而不是一句模板；被打断的流保留用户已经看到的半个答案并加一个「到此中断」标记，而不是用一句通知覆盖它（Finish 会替换整个消息窗口）；失败的副作用工具会在回复末尾留一句页脚，正面顶住模型「已经发出去了」的说法；孤儿修复补的合成结果说的是「可能已完成，不要盲目重试」而不是「失败」；一个投递彻底失败的回合宁可报错，也不肯被记成一次满意的答复。

反过来也成立：**沉默也要有理由**。一次没有可见内容的取消完全不出声（但仍然释放 sink，让攒批类 sink 的计数平衡）；一个 `stay_silent` 的退出投递空内容——而空 Finish 在跨 agent 返程 sink 上是空动，派发链因此正好在这里终止。

### 判官从不当拦路虎

两个验收闸都**判不了就放行**。一道闸的职责是拦住有依据说错的东西，不是拦住它没能验证的东西——judge 模型没部署、顾问不可用、判词解析不出来，全部通过并留下日志与 trace（trace 默认按 scope 关闭，所以一道悄悄不再把关的闸必须在日志里可见）。

成本的层级也是设计的一部分：盲判官是一次普通调用，升档裁定人是一个完整子回合（10–100 倍）。所以升档只发生在**盲判不合格之后**，每回合至多一次；顾问复核的重试上限比 RUBRIC 更低，因为每一次重做的单价差一个量级。

### 委派靠实例化，不靠抽核

「子任务」的显而易见做法是把循环抽成一个可复用的核。这里没有：子回合就是同一个 `core` 换一个 store、换一个 sink、换一份 spec 跑起来。因此子回合天然继承所有护栏、所有管道纪律、所有压缩行为——没有第二套需要同步维护的语义。而权限继承靠**把父级的通道原样传下去**：子回合拿不到父级没有的任何东西，这是一条结构性的保证，不是一份需要审查的清单。
