# skills

技能目录：一套已安装技能的**哑集合**，只负责装载与读取。谁能看见哪些、什么时候用，都不归它管。

一个技能本质上是**文本加元数据**——一段给模型读的操作指引，加上若干供上层机械执行的开关。只有少数携带脚本的技能才附带文件。

---

## 在架构中的位置

**Provides**

| 能力 | 谁在用 |
|---|---|
| `contract.SkillCatalog` | 流程（取全集）、[warrant](warrant.md)（对照授权行做对账） |
| `contract.SkillFailureSink` | agora 流程（记一次失败回合的现场快照） |

**Needs**

- `contract.PanelRegistry` — 见 [webui](webui.md)。只为在 `Start` 时挂一块面板。这是硬依赖，因为 webui 是非可选模块，不会因此把一个可选模块拖进「缺提供方就整块跳过」的陷阱。

**软连接**：`contract.LearnRegistry`（见 [learn](small-modules.md#learn)）——缺席时技能只是不学习，其余照常。

本模块是可选的：没有它，流程照跑，只是模型手上没有技能可用。它与 [tools](tools.md) 是对称的一对——一边是能执行的动作，一边是能照着做的指引，两边都是哑目录、都由 warrant 按身份投影。

## 功能

**两种来源。** 内置技能编译进二进制（embed），外置技能是管理员放进数据根下 `skills/external/` 的目录。扫描顺序是先内置后外置，**同名时外置覆盖内置**——于是一次部署可以在不改二进制的前提下替换掉某个内置技能。

**一个技能 = 一个目录。** 目录里必须有 `SKILL.md`：前导的 YAML 前言加正文（模型要照着做的原文）。同目录下可选地放若干约定文件：

| 文件 | 作用 | 谁读它 |
|---|---|---|
| `SKILL.md` | 前言 + 操作指引正文 | 模型（索引进提示词，正文按需拉） |
| `RUBRIC.md` | 交付前的评判标准 | 回合核的评判闸，**模型永远看不到** |
| `INSIGHT.md` | 累积下来的经验笔记 | 附在正文尾部一并给模型 |
| 其余文件 | 脚本、模板 | 被物化进会话工作空间后由模型执行 |

**清单在提示词里，正文按需拉取。** 系统提示只承载**索引**——名字、描述、召回线索。模型判断要用哪个，再通过 `skill_view` 工具把正文取回来。这意味着技能**一律手动触发**：没有任何自动激活的模式开关，用不用由模型在当轮自己决定。

前言里的**召回线索**是专门为这个索引设计的一栏。它不是关键词堆砌，而是三类东西：锚点（行话、专有名词、命令名，跨语言通用）、区分项（同领域的兄弟技能之间，凭什么是**这一个**），以及少量通用领域词。目的很具体——提高「任务 → 想起这个技能」的命中率，而不必让模型先把正文读一遍。这一栏容忍手写时最自然的两种写法（列表或一行逗号分隔），因为写坏它的代价不是报错，而是这个技能**从索引里静默消失**——那正好是它要对治的问题。

**附属文件物化。** 携带脚本的技能被读取时，脚本会被写进当轮会话的工作空间，模型随后用终端跑它们。三类保留文件永不外泄到工作空间：`SKILL.md`（正文已在提示词里）、`INSIGHT.md`（已附在正文尾部），以及 `RUBRIC.md`——把评分标准交给被评的模型，等于让它照着答案作弊。

**评判标准。** 一个技能可以带 `RUBRIC.md`。当这样的技能在一轮里被读取过，回合核在交付前会拿这份标准机械地审一次产物，不过就重做。目录只负责**逐字**装载它，从不摘要。

**学到的笔记。** 每个技能对学习引擎暴露成一个可优化目标：当前文本就是它累积的笔记，笔记被追加在正文尾部送给模型。笔记落盘成 `INSIGHT.md`，重启后回读。

**失败快照。** agora 流程在一个成员的回合以「降级」收尾时，会为该轮读过的每个技能记一份中等粒度的轨迹快照。这些快照是给学习引擎的失败信号——让蒸馏基于真实轨迹，而不是一个单薄的标签。

## 内部结构

### 目录与扫描（`10-registry.go`）

`FileSkills` 是 `contract.SkillCatalog` 的实现：一张按名字索引的表，加上一张按 `(来源, 名字)` 索引的笔记表。

装载的最低门槛只有三条——大小上限、前言可解析、**前言里的 name 必须等于目录名**。任何一条不过就是「记一条警告并跳过这个技能」；这是本包唯一的隔离通道，一个坏技能永远不会让整次装载失败。

笔记表刻意按 `(来源, 名字)` 而不是裸名字索引：一个内置技能积累的经验，绝不能在重扫后附到一个恰好同名的外置技能身上，反之亦然。

**符号链接一律拒绝跟随。** 直接 `ReadFile` 会跟过去，把技能目录外的文件（比如一份凭证）当成提示词文本吞进来。装载路径和附属文件遍历共用同一道守卫。

### 可靠性姿态

这块的三档行为是区分开的，值得单独讲：

| 情形 | 行为 |
|---|---|
| 外置目录**根本不存在** | 不是错误——就是没有外置技能 |
| 外置扫描出现**读取错误**（挂载竞态、权限抖动） | **fail-closed**：保持当前状态不动并报错。绝不能把一次 I/O 抖动读成「这些技能被删了」，那会连带把它们积累的笔记一并清除 |
| 启动时反复重试后仍然失败 | **fall-open** 到只有内置集，并把目录标记为 `Degraded` |

`Degraded` 这个标记是给下游看的：它宣告「本次 `List()` 已知不完整」。warrant 在对账 `skill:use:<名字>` 授权行时会先问这一句——否则一次挂载抖动就会把管理员真授出去的权限行悄悄剪掉。

反过来，一次**成功**的重扫确实会做删除侧的清理：被移除的技能会带走它的笔记与失败快照。这里还有一层细分——磁盘上**仍然存在但因为前言写坏而被跳过**的技能，不算被移除。否则编辑到一半保存一次，就会把它累积的全部经验删掉，而且不可再生。

### 学习面（`20-learn.go`）

两件东西：一是把每个技能包装成一个可优化目标（读当前笔记、交回改写后的笔记、顺带把落盘做掉）；二是失败快照的环形文件存储——按技能分目录，每份快照一个文件，超过上限丢最旧的，被消费过的在下一次读取时清掉。

快照存储的读取是**读即删**，因此它在实现里被明确标注为「学习引擎是唯一调用方」：多一个消费者就会销毁尚未蒸馏的证据。

同一套小小的环形存储机制在 tools 与 agora 里各有一份逐字节相同的副本。这是有意为之：架构规则禁止 leaf 之间互相 import，而 `contract` 是接口缝、不放文件系统机制——所以这点机制选择**镜像**而非共享，代价是改动时必须同步 diff 所有副本。

### 附属文件（`30-files.go`）

按来源分别走 embed 或磁盘遍历，逐文件与总量都有上限，保留文件被排除，符号链接被拒。保留文件的匹配不是精确相等：崩溃留下的临时文件、编辑器的备份与交换文件，都是保留名的**变体**，一样必须排除——否则评判标准就随着一个 `.swp` 溜进了模型的工作空间。

### 面板（`90-panel.go`）

一块管理员可见的面板，列出已装载技能及其来源、是否带评判标准、是否已有学到的笔记；每行带一个编辑按钮，直接就地改这个技能的笔记。编辑走的是和蒸馏改写**同一条写入路径**，所以手改与自动改写不会分叉；存成空即清除该笔记。

### 子包：`builtin/`

内置技能就是这个子目录，编译时整棵树 embed 进二进制。每个子目录一个技能，结构与外置技能**完全一致**——同样的 `SKILL.md`、同样的可选 `RUBRIC.md`、同样的脚本目录。装载器对两者只有一处差异：读字节时一边走 embed 文件系统、一边走磁盘。

随二进制发布的这一组覆盖几个方向：

| 方向 | 形态 |
|---|---|
| 通用写作、摘要 | 纯文本；讲输出结构与取舍 |
| 学术检索 | 带脚本；脚本只用标准库，不引额外依赖也不需要密钥 |
| 远端运维 | 纯文本；把「在哪台机器上跑」收敛成一个空间名 |
| 素材导入 | 纯文本；配套一个导入工具 |
| 电商 / 内容平台操作 | 纯文本；配套各自的请求工具 |

最后两类的典型形态是「配套某个工具的用法说明」——工具负责发请求与认证，技能负责告诉模型该走哪个端点、字段怎么填、什么时候**不该**用它。这类前言里几乎都写了一行「不要用于……」，把同领域的兄弟技能互相划清；那正是召回线索里「区分项」那一类要解决的事。

内置技能有一个结构上的小麻烦：它在磁盘上没有属于自己的目录，而学到的笔记需要一个可写的落点。解法是在数据根下按来源分出镜像目录，内置技能的笔记落在那里。

## 设计理据

**哑目录，投影在别处。** 目录只回答「装了什么」。「这个身份能用哪些」由 [warrant](warrant.md) 投影，「什么时候注入提示词」由流程决定。因为提示词索引与 `skill_view` 读的是**同一份投影**，可见性与可用性天然同源——不会出现「清单里列着但一调就说没权限」。

**技能一律手动触发。** 曾经设想过给技能加模式开关（自动/半自动/手动），最后砍掉了：模式是策略，而策略属于流程，不属于目录。留下的单一形态是「索引进提示词，正文按需拉」，判断权完整地留在模型当轮的推理里。

**装载失败要区分「读不到」和「没有」。** 本模块最容易犯的错，是把一次瞬时 I/O 故障当成删除。目录里绝大部分的复杂度都在这条区分上——因为「删除」这个判断是**破坏性**的：它连带清掉笔记、快照，以及下游的授权行。

**评判标准不进工作空间。** 这不是权限问题而是评测有效性问题：被评者读得到评分表，评测就失去意义。所以它在物化路径上被硬排除，连同它的所有文件名变体。

**与 tools 保持对称。** 目录形状、投影方式、学习面、面板，都刻意做成和 [tools](tools.md) 一一对应。代价是若干处小机制要维护镜像副本；收益是「工具」与「技能」在流程与授权层可以用同一套心智模型处理——一边给能力，一边给指引，两边的可见性都由同一条投影决定。
