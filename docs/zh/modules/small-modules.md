# 小模块合集

这里收七个职责单一的模块。它们小，是因为**只做一件事**，不是因为不重要——`pgpool` 提供 `contract.DB`，是整张依赖图的根；`slash` 提供的 `SlashRegistry` 被半数模块 Require。每节按「定位 / 位置 / 功能 / 结构」的微缩骨架写。

| 模块 | Provides | Needs |
|---|---|---|
| [urllib](#urllib) | `contract.URLLibrary` | `contract.DB` |
| [learn](#learn) | `contract.LearnRegistry` | `contract.PanelRegistry` |
| [pgpool](#pgpool) | `contract.DB` | —（依赖图的根） |
| [credentials](#credentials) | `contract.Broker` | — |
| [slash](#slash) | `contract.SlashRegistry` | — |
| [asr](#asr) | `contract.Transcriber` | —（软依赖 `contract.ModelPool`） |
| [claimtoken](#claimtoken) | `contract.ClaimTokens` | — |

## urllib

**URL 记忆。** 一张记录「agent 曾经成功取到过的网址」的表，外加一份搜索引擎清单。它存在的理由只有一句话：让**被证明有用过**的网址，在下一次搜索时排到原始搜索结果噪音的前面。

### 在架构中的位置

**Provides** `contract.URLLibrary` · **Needs** `contract.DB`（[pgpool](#pgpool)）

对 `contract.DB` 是**硬依赖**——这个模块本身就是那张表，没有库就没有任何东西可提供。但它对下游是**纯可选**的：网页工具与流程都用软边持有它，缺席时每个网页工具保持原有行为，不多不少。所有方法在库不存在时都是空动作或空结果，所以调用方全部 nil-safe。

上游消费者：[tools](tools.md) 里的网页搜索与抓取工具（成功取回时 `Record`，搜索时 `Recall`），以及[流程层](../flows.md)（回合以一个干净的最终答案收尾时 `MarkSatisfied`）。

### 功能

模块记录**两个信号**，且只有两个。信号①：这个网址被成功抓取过——同时把导致这次抓取的搜索词并进该行的查询列表（去重、有上限），刷新最后见到的时间。信号②：这个回合以一个像样的答案收尾，于是本轮**最后一个**被记录的网址的「满足计数」加一。

排序只用满足计数，再以最近见过的时间做次序。这里**刻意没有访问计数**：按访问频次排序是一个富者愈富的陷阱——一个门户只要被反复抓取就能长期霸占任何与它沾边的查询，而它是否真的解决过问题完全没被考虑。要上升，必须先被证明有用。

它还记两件与「怎么打开」有关的事。搜索引擎行带着自己的**连接档位**（普通请求 / 需要渲染 / 需要更强的伪装）和**语言作用域**（全局，或某个语言标签）；引擎按「档位由便宜到贵」排序返回，于是调用方的引擎数量上限总是先砍掉最贵的那些。普通内容行则按**主机**记住「上一次成功用的是哪一档」，让抓取阶梯直接从对的那一级起步，而不是每次从最底层重爬。

清扫是**价值感知**的：只删「不是引擎、从未满足过、且久未见到」的行。曾经有用或最近见过的一律留下，于是长尾被保住，被淘汰的只有一次性噪音。

### 内部结构

`00-module.go` 是外壳：迁移、播种、注册能力、挂上保留期清扫任务。`10-store.go` 是全部实体——表结构与逐版本迁移、`contract.URLLibrary` 的实现、查询列表的合并、LIKE 元字符转义、主机名归一化。`Record` 走一次事务并对该 URL 取一把顾问锁：查询列表的合并是「读—并—写」，无法用一条 UPSERT 表达，并发写入必须被串行化才不会互相覆盖。`20-seeds.go` 是引导用的种子集（几个搜索引擎与一个参考站点）；播种是幂等且**保值**的——已有行的计数与人工调整过的档位不会被覆盖，只有仍处于未设置默认值的字段才会被补上。

## learn

**文本空间的经验优化器。** 一个引擎，N 个「可训练文本」目标：一个工具描述的补充段、一份技能文档、一个角色手册。引擎从观察到的失败记录里提炼纠正经验，写回目标自己的存储。

### 在架构中的位置

**Provides** `contract.LearnRegistry` · **Needs** `contract.PanelRegistry`（[webui](webui.md)）

Needs 面板注册表是为了在 `Start` 时挂上自己的仪表盘；这是硬 Need，但提供方是必然存在的 webui，所以不会给一个 Optional 模块设下跳过陷阱。蒸馏用的模型池是**软依赖**，惰性解析：没有模型就跳过这一轮，什么都不学。

目标的**拥有方**（工具目录、技能目录、组织角色）各自实现一个 `contract.LearnSource` 并在启动时注册进来。它们因此保持「哑」的状态——不碰模型、不写提示词；引擎独占那一次模型调用和整套防腐策略。

### 功能

**只从失败学。** 成功没有纠正信号。引擎读取每个目标自上次水位线以来的记录，只留失败的那些。

**攒够了才学。** 失败数达到阈值才触发一次蒸馏；此外还有一条兜底：最老的那条失败等待超过一段时间后，即使数量不够也强制蒸馏一次——否则一个很少出错的目标会永远饿死。

**整体重写而不是增量追加。** 每次蒸馏产出的是**完整的新补充文本**，不是一段增补。这是防腐的关键：过时或写错的经验会在下一次重写中自然消失，而不是层层累积。产出有字数上限，保证它始终是一段紧凑的补充，而不是喧宾夺主的第二份说明书。

**注入防御。** 喂给蒸馏器的失败记录是**数据不是指令**，提示词里显式这么声明；工具类记录只带**参数形状**（键名与长度，从不带原始值），因此一个被构造的参数没有渠道把敌意「经验」写进后续每一份系统提示。

**不会因为一次异常就破坏已有成果。** 蒸馏器返回空内容时不覆盖已有文本；产出与现有文本一致时视为无变化；写回失败时仍然推进水位线——否则一个持续性的写入故障会让同一批失败被反复重跑，每一轮都在付真实的模型费用却零进展。

### 内部结构

`10-engine.go` 是 `contract.LearnRegistry` 的实现加扫描驱动：每轮**重新枚举**所有源的目标（动态目标随公司/角色增删，必须每轮现取），逐个蒸馏，最后清掉本轮不再出现的目标的水位线。水位线推进到**本批最新一条记录的时间**而不是完成时刻——模型调用要阻塞若干秒，期间新产生的记录时间戳会早于「完成时的墙钟」却不在这一批里，按后者推进会把它们静默吞掉。`20-distill.go` 是提示词与记录渲染。`90-panel.go` 把「注册了几个源、有几个目标、蒸馏器是否接上、每个目标上次蒸馏是什么时候」摊给界面。蒸馏扫描本身跑在 trunk 的 housekeeper 上，周期很长——学习是慢积累，不该上热路径，也不该无节制地花钱。

## pgpool

**依赖图的根。** 它拥有唯一的数据库连接池，并提供每个模块的持久化层赖以执行 SQL 的那一个接口：`contract.DB`。

### 在架构中的位置

**Provides** `contract.DB` · **Needs** 无

没有任何 Needs，所以它在拓扑排序里总是第一个 `Start`、最后一个 `Stop`；所有落库的模块都排在它后面。它是**唯一知道数据库是 Postgres 的地方**——它包住一个标准库连接池，把驱动细节挡在 `contract.DB` 后面。领域模块拥有自己的表、自己的迁移、自己的 SQL，它们 Require `contract.DB`，永远不 import 这个包的内部。

`Optional() == false`：没有数据库就什么都存不下来，连接失败必须中止启动，而不是降级。

### 功能

**一个 SQL 通用的执行面。** Exec / Query / QueryRow / Begin，加上结果、行、事务三个小接口。**没有任何驱动类型泄漏**——这是「Postgres 这件事到此为止」这条边界能够成立的原因。嵌套事务显式不支持：在事务上再 Begin 直接返回错误。

**把驱动的哨兵错误翻译成契约的。** 「查无此行」被翻成契约自己的哨兵，于是各模块的存储实现可以区分「没找到」和「真出错」，同时**不需要 import 标准库的数据库包**。

**把锁竞争分类出来。** 序列化失败、死锁、拿不到锁这几类状态码被统一映射成一个「可重试」哨兵，原错误保留在错误链里。这是调用方**唯一**允许重试的存储错误——其余错误一律不可重试，因为把一次坏写入重写一遍，只会把一行坏数据变成两行。分类点是全覆盖的：初次调用、迭代过程中暴露的错误、单行 Scan、以及**提交时**才浮现的序列化失败，四条路径都被分类。

**连接卫生。** 池子规模保守，并且主动回收连接：一个跑很多天的常驻进程，其空闲连接可能被中间的网络设备静默掐掉，而池子会毫无察觉地把一个死连接递出去。启动时用一次带超时的探活确认连通性——驱动会推迟连接串解析，所以配置写错和服务器够不着这两件事都要到这一步才暴露。

### 内部结构

`00-doc.go` 就是这个模块的边界声明本身（先读它）。`10-module.go` 是生命周期：开池、调参、探活、注册。`20-adapt.go` 是全部适配逻辑——错误分类表、`database/sql` 查询面到 `contract.DB` 的包装、行与单行的薄封装、事务实现。

**关于韧性的一个明确取舍：** pgpool 刻意**没有第二后端、也没有回退切换**。持续性故障就以普通错误的形式暴露；持久性与优雅降级是脊梁那一层的职责（入口预写与准入控制），不是靠换一个后端。正是这个简化，让早期那套「主后端 / 备后端 / 回退层」的三件套得以退役。

## credentials

**warrant 的密钥后端。** 它按名字构建出**已配置好的客户端**——而密钥本身**从不到达调用方手里**。

### 在架构中的位置

**Provides** `contract.Broker` · **Needs** 无

唯一的消费者是 [warrant](warrant.md)，而且 warrant 是**先过授权闸、再来要一个客户端**：工具永远看不到这个 broker。`Optional() == true`：没有密钥库就构建不出远程空间，本地空间照常工作，管线不受影响。

### 功能

**按种类分派构建。** 每条凭证带一个**种类**判别。种类到构建函数的映射是一张可注册的表：SSH 是内置的，其它种类由接线层在启动时注册进来——**这样一来那个种类的领域代码（以及它的类型）留在它自己的包里**，credentials 不 import 它，而构建好的客户端把密钥关在自己内部。构建函数返回一个不带类型的值，由调用方断言，于是 `contract.Broker` 这个契约面上不出现任何第三方库的类型。

**按种类枚举名字。** warrant 需要「这个授权集允许的、某个种类下的那一条凭证」，所以 broker 提供一个只读**种类字段**的枚举：它不解析、更不持有任何密钥值。

**面向调用方的错误脱敏。** 返回给调用方的错误只提凭证的**名字**——不回显任何路径。真正的底层原因（权限、IO、链接问题）只写进服务端日志；没有它，一个权限配错的密钥库将无从诊断。

**一条坏文件不拖垮其余。** 枚举时遇到读不出或格式不对的条目会**记警告并跳过**，而不是让整次解析失败。安静跳过是不行的：那条凭证会从候选集里凭空消失，把运维引向「是不是没授权」，而真正的问题在那个文件本身。

### 内部结构

`00-module.go` 是模块与 broker：`Start` 时**冻结**种类表的一份副本，于是启动后再往模块上注册种类，也不会改动 broker 正在分派的那张活映射。`10-vault.go` 是密钥库的读取与解析层——它有一个值得一提的内部约束：「只取种类」的快速路径与「取全部字段」的完整路径**共用同一个扫描器**，因此两者对任何一份输入的接受/拒绝判断永远一致（否则一份格式有问题的条目可能在枚举时被当作合法候选，到构建时才炸）。`20-ssh.go` 是内置的 SSH 构建器，其中把连接与握手都套上了超时——库本身的超时设置只覆盖到 TCP 连接，握手阶段没有截止时间，一个卡死的对端会让调用它的那个回合永远挂住。

## slash

**斜杠命令注册表。** 一张 `/...` 命令表，加上运行它们的分派。

### 在架构中的位置

**Provides** `contract.SlashRegistry` · **Needs** 无

`Optional() == false`——拥有命令的模块在 `Start` 时是 `Require`（硬取）这个注册表的。**这是它被半数模块依赖的原因**：会话、账户、模型、网关准入、组织、编排、界面……每一个有命令要暴露的模块都要它。注册表**只持有表，逻辑留在各自模块**。入站流程在准入闸之后把一个 `/...` 事件交给 `Dispatch`，而不是起一个模型回合。

注册表自己只拥有一个内置命令：`/help`——它读的正是自己那张表。

### 功能

**注册期就炸的接线检查。** 重名、空处理函数、以及**分派永远不可能匹配到的名字**（含空白、`@`、`/`——因为解析器会在这些字符上切分或剥离），一律直接 panic。这些都是接线错误，必须在启动时暴露，与能力注册表的姿态一致。名字统一按小写存放，与分派侧的小写查找对齐，否则一个大写注册的命令会永远不可达。

**分派：解析、闸、执行。** 把文本切成命令名与参数文本，管理员命令对非管理员直接回绝，未知命令渲染提示。同步执行——处理函数必须快，不允许模型调用。返回值只用于调用方判断成败，回复文本无论如何都已经通过 sink 渲染出去了。

**行结构的渲染修正。** 斜杠回复是**行结构的界面文本**——一份命令清单、一次状态转储、一张回执——由处理函数用裸换行拼出来。但不是每个通道都把裸换行读成换行：会渲染 markdown 的通道把单个换行当软换行，整段回复会被压成一个流水段落。所以分派时会按通道自己声明的分隔符改写行边界。**这个判断做在这里**，因为「这段文字是 bob 自己的界面，不是模型写的表格」正是拿到一段拼好的文本的传输层无从分辨的事。两类 sink 不做改写：分隔符本来就是裸换行的（没什么可改），以及那些产出被当作**制品**原样消费的（改写它的行尾等于编辑一份载荷，而不是修一个渲染）。

### 内部结构

`00-module.go` 是外壳：先注册内置命令（必须早于其它模块往表里加东西），再提供能力。`10-registry.go` 是全部实体——表与读写锁、注册、分派、排序列举、`/help` 的渲染、命令行解析（含把某些平台会附加的 `@机器人名` 后缀剥掉），以及上面那层行边界改写的 sink 包装。

## asr

**语音预处理。** 把入站消息里的语音/音频附件在**摄入阶段**转成文字，于是「说出来的内容」对下游所有读者（提示词、历史存储、语料投喂）就是普通文本。

### 在架构中的位置

**Provides** `contract.Transcriber` · **Needs** 无硬依赖；**软依赖** `contract.ModelPool`

模型池是惰性解析的软边——trunk 并不保证模型模块排在它前面，但到第一条入站消息到达时它一定已经注册好了。没有语音后端的部署照样提供一个 `Transcriber`，只是永远转不出东西。会话核心用软边持有它，nil 即不转写。

它与会话核心通过 trunk 耦合，**不是直接 import**。

### 功能

**按「这是谁的话」拆成两半。** 这是本模块最重要的一个判断，返回值因此有两个：

- **指令位** —— 发送者自己的、没有配文的语音条。这段转写**就是**请求本身，会像用户打字一样落进消息正文，不做净化——那是用户自己的话在用户自己的位置上，而他打的字同样不会被净化。
- **素材位** —— 其它一切带声音的东西：带配文的音频、从**被引用消息**里带进来的音频、视频的声道。这些是第三方内容，会被显式框上来源、并按引用行同样的卫生规则净化。

这个拆分才是重点。在它之前，转写被直接附到配文后面、以无框、无归属、无长度约束的形式落进用户角色——那是全项目**唯一**一条把别人的话塞进指令通道却不经过工具边界的路径（工具结果是 tool 角色，引用回复走专门的引用行与净化）。

**长片是「谢绝」不是「失败」。** 超过摄入时长预算的音频不在这里转写，而是换成一条声明其时长的说明，让模型按需用工具去取。这是个**延迟预算**而不是能力上限——摄入是同步跑在「人正在等这一轮开始」上的。两者绝不能混为一谈：失败提示会说「转写坏了、请改用文字」，对一段我们只是**选择不转**的音频，这句话既不真，又会把模型从那个仍然能取到词的工具旁边引开。超长的**视频**则安静跳过——影像片段的声道通常没有可用语音，为每个视频广告一次「有词可取」只会白花一轮工具调用；文件本身在附件列表里可见，音频工具也接受视频，所以那些词依然可达，只是不再被主动宣传。

**其余全是 best-effort。** 池子为空、文件读不到、后端报错，一律记日志后降级；**转写从不让回合失败**。语音专属的兜底只有一条：一个纯语音的回合如果转写失败，会放一条说明进指令位，免得整轮空着。

**已转写要说出来。** 成功后附件本身被标记为已转写，否则提示词里的附件列表会显示一个「看起来没人碰过」的文件，白白诱发一次重复抓取。

### 内部结构

`00-module.go` 是外壳与那个惰性池适配器。`10-asr.go` 是全部逻辑：拆分判定、转码与后端调用、时长探测、附件类型判定、转写文本的净化、以及后端输出里可能出现的包裹标记的剥除。转码把源片统一成规范采样率的单声道格式；转码与探测**共用同一个并发信号量**——它们都是每条入站音频要起的外部子进程，而这个闸的全部意义就是一次消息突发不能派生出无限多个子进程。

## claimtoken

**全项目的令牌认证设施。** 它只拥有令牌的**生命周期**：铸一个随机秘密、把 (种类, 载荷) 冻在它后面、带一个有效期存起来、验证时交还、用掉时烧毁。

### 在架构中的位置

**Provides** `contract.ClaimTokens` · **Needs** 无

`Optional() == false`：准入闸、账户、组织、界面全都靠它兑换，缺了它整套绑定 / 接线 / 放行 / 接管的入口会静默失效，所以启动失败应当中止。

### 功能

**它刻意不知道的事，比它知道的更重要。** 谁可以兑换、从哪个通道兑换（一条聊天消息？一次 HTTP 请求？）、以及一个有效令牌兑换之后**到底会发生什么**——三件事全都留在拥有它的那个模块里。种类字符串对本设施完全不透明；兑换方自己知道自己的载荷类型。

**验证与消耗分离。** `Verify` 认证但**不消耗**：拿到冻结的 (种类, 载荷)，由调用方去跑后续流程，成功（或确定性失败）之后再 `Consume`。瞬时失败——或者兑换者不符合资格——则原样留着令牌，**保持它原本的到期时间**（不做截断），于是用户可以拿同一个码再试一次。`Consume` 是幂等的。

**过期有两条路。** `Verify` 上惰性回收命中的过期项，另有一个周期性扫描回收那些**从未被兑换**的铸造。正确性只靠前者——后者只是回收内存。

**一个有意的边界。** 服务之间用静态密钥做的认证**不是**认领令牌：那里没有用户业务，不属于这套设施。

### 内部结构

单文件模块。令牌表是一张受互斥量保护的内存映射；令牌是密码学随机数的十六进制串。清扫跑在**模块内自己的 ticker** 上，而**不是** trunk 的 housekeeper——housekeeper 保留给持久化（数据库/文件）扫除，纯内存的卫生自己转一个定时器就好，这与界面鉴权、工具通道池的做法一致。
